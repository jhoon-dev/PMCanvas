# PM Canvas Desktop 0.8.3

[개인정보처리방침 / Privacy policy](PRIVACY.md). 앱의 **파일 옵션 → 개인정보처리방침** 또는 네이티브 **파일** 메뉴에서도 확인할 수 있습니다.

macOS의 App Store 배포는 [Mac App Store 설정·빌드·제출 안내](MAC-APP-STORE.md)를 따릅니다. Apple Silicon·Intel universal MAS 빌드를 지원하며, 서명·샌드박스 실행·심사·실제 게시 상태를 별도로 확인합니다.

형제 shared/ 폴더의 계산·검증 코드를 사용하는 Windows·macOS용 오프라인 앱의 개발 초기 버전입니다. 사용자 PC에는 Node.js·Docker·PostgreSQL 설치가 필요하지 않습니다.

빈 프로젝트는 참여인력 → 첫 업무 → 완료 기록 순서로 시작을 안내합니다. 업무 입력창은 이름·담당자·일정·체크리스트를 먼저 보여주며, **분류 · 선행 업무 · 메모**를 펼치면 상위 업무와 추가 설정을 수정할 수 있습니다. 기존 상위·선행 업무나 메모가 있으면 자동으로 펼쳐집니다. 검색 중에는 **필터 초기화**로 전체 업무로 돌아올 수 있으며 입력·완료 기록은 유지됩니다. 상단 실행 취소·다시 실행은 작은 화살표로 표시하며 키보드 단축키도 사용할 수 있습니다.

Windows의 새 배포 경로는 [Microsoft Store 제출용 MSIX](WINDOWS-STORE.md)입니다. Partner Center 앱 예약 후 제품 ID를 설정하면 CI에서 제출 파일을 만들 수 있습니다. 아직 Store에 게시한 상태는 아니며 기존 공개 EXE는 호환용으로 유지합니다. Mac의 [인증서 발급 → 공증 → GitHub Secrets 등록 순서](MAC-SETUP.md)도 단계별로 안내합니다.

Mac이 없어도 Windows에서 `npm --prefix desktop run signing:setup`으로 개인 키·CSR 생성, Apple 발급 안내, P12 변환·검증, GitHub Secrets 등록을 이어서 진행할 수 있습니다. 개인 키는 Git 밖에 암호화해 보관하며 입력한 암호를 파일이나 로그에 남기지 않습니다. 자세한 사용법은 [Mac 설정 가이드](MAC-SETUP.md)를 참고하세요.

앱 시작 시 새 버전을 백그라운드에서 확인하고, 설치 가능한 업데이트가 있으면 작업 화면 위에 작은 알림을 표시합니다. 열린 입력창과 미저장 내용은 유지됩니다. **파일 옵션 → 앱 설정**에서 **앱 시작 시 새 버전 확인**을 끄거나 켤 수 있으며, **업데이트 확인**으로 언제든 다시 확인할 수 있습니다. 시작 시 네트워크 오류는 작업을 중단하지 않습니다.

**Microsoft Store 버전**은 현재 앱의 업데이트를 Windows Store API로 확인하며 **Microsoft Store에서 업데이트** 버튼으로 Store의 업데이트 화면을 엽니다. Store 앱 등록·연결이 아직 완료되지 않았거나 확인할 수 없는 환경이면 그 상태를 표시하고 Store에서 직접 확인할 수 있게 합니다. 실제 Store 게시 후 신규 패키지 감지는 계정·지역·배포 시점에 따라 달라질 수 있습니다.

**Mac·기존 EXE 버전**은 공식 GitHub Release에서 현재 운영체제·아키텍처의 안정 버전을 찾습니다. 0.8.1부터 **업데이트 다운로드**를 누르면 앱에 내장된 공개키로 `update-manifest.json`의 Ed25519 서명을 검증하고, 승인된 버전·파일명·SHA-256·크기와 설치 파일이 일치하는지 확인합니다. 서명 정보가 없거나 변조되면 설치 파일을 실행하지 않습니다. 검증 완료 후 **설치 파일 열기**로 설치를 진행하며 실행 직전에도 다시 검증합니다. 미저장 내용·열린 입력창·가져오기가 있으면 먼저 정리하도록 안내합니다. 자동 확인만으로 다운로드·설치·재시작을 실행하지 않습니다.

업데이트 서명은 OS 코드 서명·Mac 공증과 별개입니다. 기존 0.8.0 앱에 새 검증 기능을 소급 적용할 수 없으므로 처음 전환할 때는 검증된 공식 설치 파일을 사용합니다. [업데이트 서명과 CI 운영](UPDATE-SECURITY.md)

업데이트 캐시는 사용자 프로필의 `updates/`에서 검증 후 재사용합니다. 기본 보관 기간은 7일, 완료된 다운로드는 최대 2개 폴더·전체 1GiB로 제한합니다. 진행 중인 파일과 현재 사용 중인 파일을 보호하고 오래된 공용 임시 캐시도 정리합니다. 프로젝트·복구 사본·사용자 설정은 정리하지 않습니다.

설정 JSON이나 시간대가 손상되면 원본을 `preferences.json.invalid-<SHA256>` 사본에 보관하고 기본값으로 실행합니다. 보존할 수 없는 원본은 덮어쓰지 않습니다. 앱 설정에서 복구 안내와 시간대·자동 확인 값을 확인할 수 있습니다.

복구 파일을 읽지 못한 경우에도 원본을 `recovery.json.invalid-<SHA256>`으로 보존합니다. 새 프로젝트를 만들거나 다른 파일을 열어도 이 사본은 유지됩니다. 사본을 안전하게 만들 수 없으면 복구 원본 교체를 거절합니다. 프로젝트 저장 시에는 Windows 대소문자·경로 별칭·하드 링크로 같은 파일을 가리키는 경우에도 외부 변경 충돌을 검사합니다.

프로젝트·계정·파일 경로는 업데이트 서버에 보내지 않습니다. 프로젝트 파일과 PC 설정은 기존 위치에 보존하며, 오프라인에서도 편집과 저장을 계속 사용할 수 있습니다. Windows Store 버전은 GitHub 설치 파일을 사용하지 않습니다.

설치 파일은 [데스크톱 Release](https://github.com/jhoon-dev/PMCanvas/releases?q=desktop-v)에서 받습니다. 프로젝트를 먼저 저장하고 앱을 종료한 뒤 새 설치 파일을 실행하세요. 프로젝트는 설치 폴더 바깥에 보관합니다. 서명·공증 없는 임시 배포 파일은 발급자 신뢰를 제공하지 않으므로 Release의 체크섬과 빌드 상태를 확인하세요.

**파일 옵션 → 업무 기준 시간대**에서 IANA 시간대를 지정할 수 있습니다. 기본값은 `Asia/Seoul`이고 설정은 이 PC에 보존됩니다. 오늘·완료 체크·보고서가 같은 시간대를 사용하며 기존 일정과 완료일은 변환하지 않습니다. 변경사항·열린 입력창·Excel 가져오기를 먼저 저장하거나 취소하세요. 새 기준에서 기존 완료일이 미래가 되는 변경은 거절하여 기록을 보호합니다.

## 사용 범위

- 프로젝트 현황: 공수 가중 진척률, 계획 진척률, 예상 완료일, 지연 업무.
- 업무 · 일정: 업무·담당자·시작/종료일·선행 업무·세부 체크리스트, 조회용 간트.
- WBS · 기준 계획: 상위 업무 지정·들여쓰기/내어쓰기·접기, 하위 포함 공수·진척률·기간 집계, 기준 계획 저장과 변경 비교.
- WBS 일괄 작업: 여러 업무 선택·복제·순서 이동·삭제, 적용 전 변경 확인과 실행 취소.
- 일정 점검·조정: 선행 충돌·담당자 과부하·임계 업무 확인, 일정 이동·기간 조정·후속 일정 정리와 적용 전 미리보기.
- 완료 체크: 보고 기준일에 실제 완료 기록. 미래 날짜 입력 제한.
- 참여인력: 이름·역할·등급·하루 근무시간·투입률.
- 보고서: 기준일별 업무 현황, 기간·담당자별 완료 기록 조회와 Excel(.xlsx)·CSV 저장.
- Excel: 입력 양식 저장, 시트·열 연결, 오류 미리보기 후 새 업무 추가 또는 ID로 기존 업무 갱신.
- 파일: 새 프로젝트, 열기, 저장, 다른 이름으로 저장, 웹 JSON 가져오기/내보내기.
- 입력 적용 시 복구 사본 저장. 재시작 시 미저장 작업 복구와 최근 문서 다시 열기.
- 종료·새 문서·열기 시 미저장 변경 보호. 외부 파일 변경은 덮어쓰기 차단.
- 프로젝트 변경 실행 취소·다시 실행. 저장 기준 상태와 완료 기록·계층·기준 계획 보존.

파일 하나가 프로젝트 하나입니다. `.pmcanvas`는 기존 `pm-canvas-project` 버전 1 JSON 형식을 사용합니다. 웹에서 백업한 JSON은 원본을 덮어쓰지 않도록 새 문서로 가져옵니다. 웹으로 옮길 때는 **파일 옵션 → 웹 JSON 내보내기** 후 웹 버전에서 불러옵니다.

상단의 **실행 취소 / 다시 실행** 또는 **프로젝트** 메뉴에서 적용한 프로젝트 변경을 되돌립니다. 단축키는 Windows에서 `Ctrl+Alt+Z` / `Ctrl+Alt+Y`, macOS에서 `Cmd+Alt+Z` / `Cmd+Alt+Y`입니다. 입력창의 일반 텍스트 실행 취소와 구분하며, 입력창·Excel 가져오기를 먼저 적용하거나 취소해야 합니다. 이력은 현재 앱 세션에서 최대 20단계로 보관하고 각 방향의 메모리를 16MB로 제한하므로 큰 프로젝트에서는 단계가 줄어들 수 있습니다. 새 프로젝트·파일 열기·앱 재시작 때 이력은 초기화됩니다.

마지막으로 저장한 내용까지 되돌리면 미저장 표시가 해제됩니다. 저장 이후에도 이력을 사용할 수 있으며, 다른 이름으로 저장한 뒤 실행 취소해도 현재 파일 경로를 유지합니다. 실행 취소·다시 실행은 프로젝트 파일을 자동으로 덮어쓰지 않습니다. 새 변경을 적용하면 다시 실행 이력이 초기화됩니다. 복구 사본 쓰기에 실패하면 문서와 이력을 함께 보존하며, 기존 복구 파일도 읽을 수 있습니다.

웹의 WBS 계층·기준 계획은 파일에서 보존하며 **WBS · 기준 계획**에서 편집·비교할 수 있습니다. 웹에 미확정 WBS 입력이 있으면 웹에서 먼저 저장한 후 다시 백업해야 합니다. 계정·권한 정보는 가져오지 않습니다.

업무 편집의 **상위 업무**에서 묶음 관계를 지정합니다. WBS 화면의 화살표는 앞의 같은 수준 업무 아래로 들여쓰기하거나 한 수준 내어쓰기합니다. 업무 이름 옆 삼각형으로 하위 업무를 접습니다. 검색·담당자 필터를 사용하면 일치하는 업무와 상위 경로를 펼쳐 표시합니다. 묶음의 공수·진척률·기간에는 해당 업무 자체와 모든 하위 업무가 포함되며, 전체 프로젝트 공수에 중복 가산하지 않습니다.

WBS의 체크박스로 여러 업무를 선택하고 **선택 복제 / 위로 / 아래로 / 삭제**를 실행합니다. 머리글 체크박스는 표시된 업무를 모두 선택합니다. 검색·담당자 필터·접기/펼치기·화면 이동 시에는 선택을 해제합니다. 복제할 하위 업무도 함께 선택하세요. 복제본은 미완료로 만들고 함께 선택한 상위·선행 관계는 복제본끼리 연결합니다. 원본의 완료 기록과 기준 계획은 유지합니다.

순서 이동은 전체 WBS에서 같은 상위 업무 아래의 순서를 바꾸며 하위 묶음을 함께 옮깁니다. 상위와 하위를 모두 선택하면 하위의 내부 순서를 유지합니다. 삭제 시 남는 직속 하위 업무는 최상위로 옮기고 삭제한 업무를 선행 업무로 참조하는 연결은 해제합니다. 적용 전 미리보기에서 대상과 영향을 확인합니다. 취소는 문서를 바꾸지 않으며 각 일괄 작업은 실행 취소 한 번으로 되돌릴 수 있습니다. 문서가 변경되면 이전 미리보기로 적용할 수 없습니다.

**기준 계획 저장**은 현재 업무 이름·계층·일정·공수를 한 세트 보관합니다. 이후 전체 업무의 추가·삭제·이름·계층 변경과 시작일·종료일·공수 차이를 비교합니다. 날짜 차이는 달력 일수이며 +는 늦어짐입니다. **기준 계획 교체**는 기존 한 세트를 바꾸므로 이전 계획이 필요하면 먼저 프로젝트 파일을 다른 이름으로 저장하세요. 변경한 계층과 기준 계획은 적용 후 프로젝트 파일을 저장해야 보관됩니다.

WBS 아래 **일정 점검**은 전체 업무의 선행 일정 충돌·담당자 과부하·CPM 임계 업무를 표시합니다. 과부하는 계획 공수를 근무일에 균등 배분하고 일 근무시간 × 투입률과 비교합니다. 주말·휴무일을 제외하며, 실제 근무 기록은 아닙니다. 임계 업무는 계획 기간·현재 시작일·선행 관계 기준 여유일이 0인 업무이며 자원 평준화는 포함하지 않습니다.

각 업무의 **일정** 또는 점검 패널의 **일정 조정**에서 시작·종료 이동이나 한쪽 날짜 조정을 선택하세요. 이동 일수는 달력 기준이며, 후속 업무도 필요하면 뒤로 조정할 수 있습니다. **전체 선행 관계에 맞춰 후속 일정 정리**는 연결된 모든 충돌을 조정합니다. **일정 변경 미리보기**에서 모든 변경 전·후 날짜를 확인한 다음 **적용**합니다. 입력 변경이나 문서 변경 후에는 다시 미리보기해야 합니다. 취소는 문서를 바꾸지 않으며, 적용한 일정은 완료 기록·공수·기준 계획을 보존합니다. 파일에 보관하려면 별도로 저장하세요.

보고서 화면에서 **파일 형식**을 Excel 또는 CSV로 선택하고 저장하세요. Excel 업무 현황에는 WBS·세부 작업·간트가 포함됩니다. 완료 기록은 조회 기간과 담당자를 반영합니다. 날짜·공수·진척률은 Excel 데이터 형식이며 사용자 입력은 수식이 아닌 문자열로 저장합니다. CSV의 UTF-8 BOM과 수식 주입 방지도 유지합니다. 입력창에서 적용한 미저장 변경도 포함하지만 프로젝트 파일의 저장 상태는 바꾸지 않습니다.

**파일 옵션 → Excel 입력 양식 저장**에서 양식을 만들고 WBS 시트에 입력하세요. 담당자는 현재 프로젝트의 참여인력을 사용합니다. **Excel 가져오기**에서 파일·시트·열을 연결하고 **미리보기 → 프로젝트에 적용**을 누릅니다. 적용 전에는 문서를 바꾸지 않으며, 적용 후에도 프로젝트 파일은 별도로 저장해야 합니다. 원본 Excel 파일은 덮어쓰지 않습니다. 기존 업무 갱신은 내보낸 업무 ID를 사용하고, 생략한 업무·완료 기록·변경하지 않은 세부 작업을 보존합니다.

가져오기는 XLSX 4MB·시트 12개·머리글 포함 501행·40열까지 지원합니다. 수식·오류 셀·매크로·내장 개체·외부 연결·DTD·손상된 체크섬은 거절합니다. 압축 해제 총량은 32MB이며 파일 처리는 제한된 별도 프로세스에서 수행합니다. 오래된 미리보기와 문서 revision이 바뀐 결과는 적용할 수 없습니다. 전체 프로젝트 이동·백업에는 기존 JSON/PM Canvas 파일을 사용하세요.

로그인·회원가입·공유·동시 편집·메일·SSO·서버 운영 기능은 포함하지 않습니다. 파일 연결·다중 창은 후속 범위입니다. 복구 사본은 별도 백업을 대신하지 않습니다. 입력창에서 아직 적용하지 않은 텍스트는 복구 대상이 아닙니다.

## 개발 실행

Node.js 22.18 이상을 사용합니다. 최초 설치에는 npm 저장소와 Electron 다운로드 서버에 접속할 수 있어야 합니다.

```sh
cd desktop
npm ci
npm start
```

`package-lock.json`에 고정한 의존성을 설치합니다. 최초 실행 시 Electron 바이너리가 추가로 다운로드될 수 있습니다.

## 검증

```sh
# desktop/에서
npm test

# 아래 두 검증은 web/ 폴더의 npm ci도 필요합니다.
npm run test:renderer
npm run test:app

# Windows 패키징 후, 패키지에 들어간 ASAR로 동일한 실제 앱 검증
npm run test:app -- dist/win-unpacked/resources/app.asar

# Windows에 실제로 설치한 EXE 검증 (PowerShell, 별도 임시 사용자 데이터 사용)
npm run test:app -- --installed "$env:LOCALAPPDATA\Programs\PM Canvas Desktop\PM Canvas Desktop.exe"
```

화면 검증에는 Playwright Chromium이 필요합니다. 최초 한 번 web/에서 `npx playwright install chromium --only-shell`로 설치합니다. 파일·복구·스키마·계산 검증은 Electron 없이 실행됩니다. 실제 앱 검증은 Electron으로 네이티브 창·격리된 브리지·파일 저장·재시작을 확인합니다.

2026-10-28 Windows x64 현재 사용자 설치 기준으로 0.2.0의 설치·실제 EXE 실행·제거·재설치를 검증했습니다. 설치된 파일·버전·등록 정보·바탕 화면/시작 메뉴 바로가기를 확인했고, 제거 후 설치 폴더·등록 정보·바로가기가 모두 없어졌습니다. 재설치 후 Windows 설정의 설치된 앱 목록에 0.2.0이 표시됐으며 실제 설치된 EXE의 저장·CSV/XLSX·가져오기·재시작 검증도 다시 통과했습니다. 원본 프로젝트와 복구 파일의 SHA-256은 전체 과정에서 유지됐습니다. 제거 검증은 Windows 파일 탐색기에서 실행한 진단 결과를 기준으로 합니다. macOS 실행 검증은 아직 완료하지 않았습니다.

Windows 설치·제거 상태를 반복 확인하는 읽기 전용 검증 도구입니다. 설치와 제거는 별도로 실행하며, 이 스크립트는 기존 앱을 설치하거나 제거하지 않습니다. `Baseline`은 첫 설치·제거 전에 한 번 실행하고, 검증 도중에는 덮어쓰지 마세요. 자동화 프로세스와 실제 탐색기에서 동일한 HKCU 조회 결과가 달랐던 환경을 확인했으므로, 자동화 환경에서는 설치 프로그램과 아래 진단 프로그램을 일반 Windows 파일 탐색기에서 실행한 결과를 사용합니다.

```powershell
# desktop/에서. 필요한 경우 보존할 프로젝트 파일을 명시합니다.
.\test\windows-install-check.ps1 -Mode Baseline -PreserveFile 'C:\Projects\Project.pmcanvas'
.\test\windows-install-check.ps1 -Mode Installed
# Windows에서 앱 제거를 완료한 뒤
.\test\windows-install-check.ps1 -Mode Removed
```

실제 사용자 환경의 등록 정보와 데이터 보존을 확인하려면, 설치 빌드가 내려받은 NSIS 컴파일러로 `test/registry-check.nsi`를 컴파일합니다. 예를 들어 기본 캐시를 사용하는 Windows 환경에서는 다음과 같습니다.

```powershell
# desktop/test/에서. PROJECT_FILE은 보존할 파일이며 진단은 읽기만 합니다.
$nsisCompiler = Get-ChildItem "$env:LOCALAPPDATA\electron-builder\Cache\nsis" -Recurse -Filter makensis.exe | Sort-Object LastWriteTime -Descending | Select-Object -First 1 -ExpandProperty FullName
& $nsisCompiler /V2 '/DPROJECT_FILE=C:\Projects\Project.pmcanvas' registry-check.nsi
```

생성된 `desktop/test-results/PMCanvas-Registry-Check.exe`를 **일반 파일 탐색기에서** 실행하면 같은 폴더에 `windows-desktop-registry.txt`가 생성됩니다. 자동화 도구의 실행 명령으로 진단 EXE를 시작하면 검사 환경의 차이가 그대로 남을 수 있습니다. 생성된 보고서는 10분 이내에 다음과 같이 사용합니다.

```powershell
# desktop/에서. Installed 또는 Removed에 실제 상태를 지정합니다.
.\test\windows-install-check.ps1 -Mode Removed -RegistryEvidence .\test-results\windows-desktop-registry.txt
```

기본 설치 위치를 바꿨다면 모든 명령에 동일한 `-InstallDirectory`를 전달하세요. 결과 JSON은 `desktop/test-results/`에 저장합니다. `Installed`는 빌드한 ASAR와 설치본을 비교하므로 먼저 동일 버전의 Windows 빌드가 필요합니다. 별도 출력 폴더의 빌드를 비교할 때는 `-ExpectedArchive`로 해당 `resources/app.asar` 경로를 지정합니다. `--installed` 앱 테스트는 임시 사용자 데이터 경로가 적용되었는지 확인한 뒤 테스트 문서를 만들며, 실제 사용자 프로젝트를 수정하지 않습니다.

## 설치 파일 빌드

제거 중 작업 경로가 설치 폴더를 잠그지 않도록 `build/installer.nsh`에서 임시 폴더로 변경합니다. 등록 정보와 바로가기 정리는 electron-builder의 표준 제거 프로그램이 수행하며, 프로젝트·복구 데이터 삭제는 비활성화했습니다. 검사 환경의 차이를 등록 정리 결함으로 오인해 추가했던 별도 정리 도우미는 제거했습니다.

각 운영체제에서 해당 명령을 실행합니다.

| 환경               | 명령                   | 결과                                       |
| ------------------ | ---------------------- | ------------------------------------------ |
| Windows x64        | `npm run dist:win`     | Microsoft Store 제출용 `.msix`             |
| Windows x64 개발용 | `npm run dist:win:dev` | 서명·실행 파일 리소스 편집을 생략한 `.exe` |
| macOS              | `npm run dist:mac`     | Apple Silicon·Intel용 `.dmg`와 `.zip`      |
| 현재 OS 압축 전 앱 | `npm run pack`         | 패키징된 앱 디렉터리                       |

결과는 `desktop/dist/`에 생성됩니다. Windows 기본 배포는 `dist:win`으로 만드는 MSIX를 Partner Center에 제출하는 방식이며 [Store 설정](WINDOWS-STORE.md)이 필요합니다. `dist:win:dev`는 기존 EXE 개발·호환용이며 별도 인증서가 있는 EXE 배포에는 `dist:win:legacy`를 사용합니다.

저장소의 **Desktop verification and builds** 워크플로는 푸시·PR에서 Windows·macOS 파일·화면·날짜/언어·실제 앱과 패키징 후 실행을 자동 검사합니다. 정식 서명 빌드는 별도 수동 실행과 인증서 설정을 사용합니다. [서명·공증 설정](SIGNING.md)을 참고하세요.

배포본은 앱 파일 허용 목록만 포함하며 웹 서버의 환경설정·키·백업·운영 데이터·계정 의존성을 포함하지 않습니다. Windows·Mac 앱, 앱 내부와 Store 타일은 기존 Windows 원자 모양 아이콘으로 통일합니다. 원본과 재생성 방법은 [아이콘 안내](build/ICONS.md)를 참고하세요.

정식 배포는 선택한 플랫폼의 서명과 설치·업데이트·제거 검증을 통과해야 합니다. CI에서 `platform=mac`, `signed=true`, `publish=true`를 선택하면 Windows 인증서 없이 Mac 서명·공증·검증 후 GitHub Release에 자동 공개할 수 있습니다. 인증서와 공증 자격 증명은 [서명·공증 설정](SIGNING.md)에 따라 등록하세요. 기존 웹 버전의 배포 ZIP과 별도 제품으로 관리합니다.

## 구조

- `scripts/prepare.mjs`: shared/의 명시한 공통 모듈만 `app/`에 준비.
- `ui/`: 여섯 화면과 편집창. 계산 엔진과 인력·업무 편집 모델 재사용.
- `ui/planning-ui.js`: WBS 계층·집계·기준 계획 비교와 상위 업무 선택.
- `main.mjs`: 네이티브 창·메뉴·파일 대화상자·종료 보호.
- `preload.cjs`: 화면에 필요한 제한된 문서 API만 노출.
- `document.mjs`: 검증·파일 저장·복구·외부 수정 검사.
- `reports.mjs`: 보고서 조건 검증·공통 집계·CSV 생성. 파일 경로는 네이티브 저장창에서 선택.
- `assets.mjs`: 앱 프로토콜의 공개 리소스 허용 목록.
- `test/`: 파일 테스트·화면 통합 테스트·실제 Electron 통합 테스트.

렌더러는 Node.js 접근 없이 sandbox·context isolation 상태로 실행합니다. 앱은 포트를 열지 않으며 외부 콘텐츠·새 창·권한 요청을 차단합니다. 복구 데이터는 Electron의 사용자별 앱 데이터 폴더에 저장됩니다. 개발 통합 테스트에서만 `PMCANVAS_DESKTOP_DATA`로 임시 경로를 지정할 수 있으며 패키지에서는 무시합니다.

## 0.7.0

자정·화면 복귀 시 기본 조회일과 최근 7일을 갱신하며, 편집 중 입력과 직접 선택한 과거 날짜·조회 기간을 보존합니다. 한국어·영어 선택은 화면·네이티브 메뉴·보고서에 적용하고 선택을 유지합니다. 미저장 변경과 편집창이 있으면 언어 변경을 막습니다. 사용자 이름·업무·메모는 번역하지 않습니다.

선택 업무가 없으면 일괄 작업 도구를 숨기고 좁은 WBS에서는 선택 열과 업무 이름을 고정합니다. 파일 옵션의 앱 정보에서 버전·기준 커밋을 확인할 수 있습니다.

정식 dist:win/dist:mac 명령은 커밋·공개 파일·서명/공증 설정을 확인합니다. 인증서 없이 확인할 때는 기존 dist:win:dev 또는 pack 명령을 사용하세요. 설정과 GitHub Secrets는 [SIGNING.md](SIGNING.md)를 참고하세요.
