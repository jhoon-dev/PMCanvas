# 공통 코드

`web/`, `desktop/`, `mobile/`이 함께 사용하는 원본 코드입니다. 공통 코드는 어느 제품 폴더에도 의존하지 않습니다.

| 경로                                                                        | 내용                                           |
| --------------------------------------------------------------------------- | ---------------------------------------------- |
| `browser/engine.js`                                                         | 근무일·공수 가중 진척률·예상 완료일            |
| `browser/task-model.js`                                                     | 요약 업무·실제 업무·복수 선행·기존 데이터 전환 |
| `browser/planning.js`                                                       | WBS 계층·기준 계획·선행 관계                   |
| `browser/html.js`, `browser/i18n.js`, `browser/locales/`                    | 안전한 HTML 출력·언어                          |
| `browser/people-view.js`, `browser/project-editor.js`, `browser/view-ui.js` | 인력 화면·편집 모델·표현 도구                  |
| `browser/reports.js`, `browser/styles.css`                                  | CSV 모델·공통 스타일                           |
| `model/project.mjs`, `model/errors.mjs`                                     | 프로젝트 검증·입력 정규화·공통 오류            |
| `assets.mjs`                                                                | 웹에 공개할 공통 브라우저 리소스 목록          |

웹은 기존 브라우저 URL을 유지하면서 허용된 공통 리소스를 직접 제공합니다. `web/public/`의 작은 재노출 모듈과 `web/server/`의 모델 재노출 모듈은 기존 내부 import 경로의 호환 계층입니다. 원본을 복제하지 않습니다.

`browser/wbs-model.js`와 `browser/excel-import-model.js`는 XLSX 열 연결·새 업무 추가·ID 갱신의 공통 모델입니다. `node/excel.mjs`와 `node/excel-import.mjs`는 양식·보고서 생성과 제한된 XLSX 파싱을 담당합니다. 각 제품이 고정 의존성을 주입하므로 공통 코드가 어느 제품의 node_modules에도 의존하지 않습니다. 데스크톱 준비 단계는 명시한 Node 모듈을 앱 내부로 복사하며, 이 모듈들은 브라우저 공개 허용 목록에 넣지 않습니다.

데스크톱은 패키징 준비 단계에서 이 폴더의 명시한 파일만 앱 내부로 복사합니다. 모바일은 Vite가 공통 브라우저·검증 모듈을 번들에 포함합니다. 웹의 서버·설정·DB·운영 의존성은 패키징하지 않습니다. 공통 코드의 수정은 이 폴더에서 진행하고 제품별 테스트를 실행하세요.

## 예상 완료일

보고 기준일 종료 후의 남은 공수를 다음 근무일부터 배정합니다. 업무별 계획 속도는 공수 ÷ 계획 근무일이며 담당자 가용시간·선행 관계를 함께 반영합니다. 계획 진척·예측・일정 점검에는 `projectHolidays(project)`로 합친 수동 휴일과 활성화된 한국 공휴일을 동일하게 적용합니다.

휴일이나 주말만 있는 업무도 불러오기·저장·복구를 허용합니다. 공휴일 갱신으로 기존 프로젝트가 열리지 않거나 서버의 기존 값 재검증이 수정을 막지 않도록, 근무일 유무는 저장 검증 대신 일정 점검의 경고로 표시합니다. 경고에는 업무 이름·날짜·수정 안내가 있으며 요약 업무와 마일스톤은 제외합니다. 날짜 형식·역전·기간 한도·담당자·선행 관계·공수 검증은 유지합니다.

근무일이 0인 일반 업무는 예상 속도와 CPM 기간에 최소 1일을 사용하고, 계획 진척은 계획 종료일 전에는 0, 종료일부터 전체 공수를 반영합니다. 휴일에 실제 작업 시간을 배정하지 않으며 다음 근무일부터 담당자 가용시간으로 예상 작업을 배정합니다. 날짜와 공수를 자동으로 바꾸지 않으므로 경고를 확인한 뒤 필요하면 일정 또는 휴무일 설정을 수정할 수 있습니다.

새 주간보고의 현재 계획 곡선과 기준 계획 곡선은 모두 `planned()`를 사용합니다. 기준 계획의 집계 공수를 계산용 항목으로 변환하고 요약 업무는 제외하므로 휴일 전용 업무도 공수가 빠지거나 중복되지 않습니다. 이미 발행한 보고서 사본은 다시 계산하지 않습니다.

최근 최대 10근무일에서 최소 3근무일이 지나고 서로 다른 2일에 완료가 있어야 실적을 관측합니다. 관측 속도는 `rawRatio = 완료 공수 / 해당 기간 계획 공수`입니다. 완료 공수는 완료 항목의 예상 시간이며 실제 투입시간이 아닙니다.

실적이 적을 때는 다음 규칙으로 계획 속도와 혼합합니다.

```text
평균 계획 일공수 = 관측 기간 계획 공수 / 관측 근무일 수
실적 비중 = min(1, 관측 근무일 수 / 10)
          × min(1, 서로 다른 완료 날짜 수 / 5, 완료 공수 / (평균 계획 일공수 × 3))
적용 속도 비율 = 실적 비중 × 관측 속도 비율 + (1 - 실적 비중) × 1
```

관측 조건을 충족하지 않으면 비중은 0입니다. 10근무일·5개 완료 날짜·계획 3일분의 완료 공수가 모이면 비중이 1이 되어 실적을 그대로 사용합니다. 비율을 임의의 상하한으로 자르지 않으며 인력 화면에 원래 관측 비율과 적용 비율을 함께 표시합니다. 일부 미완료 업무가 계획 또는 혼합 추정을 사용하면 프로젝트 현황에도 기록 부족을 표시하고, CSV·Excel 추정 방법에도 혼합 여부를 표시합니다.

이 비중은 통계적 신뢰도가 아닌 안정화 규칙입니다. 체크가 적거나 몰아서 입력되면 실제 지연을 과소 반영할 수 있으므로 계획 대비 실제 진척과 원래 관측 속도를 함께 확인합니다. 담당자 미지정·가용시간 부족·계산 범위 초과는 계속 계산 대기로 표시합니다.
