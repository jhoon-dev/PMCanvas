# 코드 리뷰 대조와 반영 · 0.19.0

제공된 리뷰의 우선순위에 대체로 동의합니다. 짧은 기간 동안 기능을 추가한 만큼 코드 가독성과 실제 사용 흐름, 복구 운영을 안정시키는 작업이 필요했습니다. 다만 리뷰에는 0.18 이전 또는 커밋 전 상태를 기준으로 한 항목이 섞여 있습니다.

0.18 기준 테스트는 단위/요청 132개 + 실제 HTTP/SMTP 13개 + 실제 PostgreSQL 17개로 총 162개였습니다. 리뷰의 122개는 이전 단위/요청 테스트 수입니다. 로그인에는 계정 부재용 해시 검증을 사용하지만 모든 요청의 전체 응답 시간이 정확히 동일하다고 보장하는 것은 아닙니다. audit·CodeQL 결과가 0이어도 취약점이 없다는 증명은 아니므로 권한·경합·입력 검증과 실제 사용 흐름을 계속 함께 확인합니다.

Prettier의 고정 버전·ignore·CI check는 [공식 설치 지침](https://prettier.io/docs/install.html)을 따랐습니다. xmldom 보안 수정과 LTS 릴리스는 [공식 릴리스](https://github.com/xmldom/xmldom/releases/tag/0.8.15), [보안 정책](https://github.com/xmldom/xmldom/security/policy)을 확인했습니다.

## 0.19.1 재검토

복원 점검의 `migrations < 12` 지적은 맞다. 백업 이미지에 실제 마이그레이션 파일을 포함하고, 복원 DB의 버전 목록 전체가 이 파일 목록과 같은지 확인하도록 수정했다. 현재 013만 검사하는 상수로 바꾸지 않아 이후 파일 추가에도 동일한 검증을 적용한다. 복원 점검 중 스키마를 변경하지는 않는다.

`recovery-keys/`는 이전 버전의 사본을 안전하게 이동시키는 임시 위치다. 이동 직후 실제 경로와 함께 프로젝트 외부의 별도 보관 장소로 옮기라고 명시했다. 전체 호스트 백업의 수집 범위는 운영자가 관리해야 한다.

app.js의 WBS·대시보드 분리는 타당한 후속 개선이다. 줄 수 자체를 보안 결함으로 보지는 않으며, 현재 포맷·기능별 모듈과 테스트를 유지하면서 다음 유지보수에서 분리할 수 있다. 이번 검증에서는 실제 화면의 회원가입부터 완료 체크까지 다시 시연했다.
