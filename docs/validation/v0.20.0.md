# 검증 결과 · 2026-10-26 · 0.20.0

- 한국어·영어 문구·표시 속성과 사용자 데이터를 분리했다. 언어·저장 상태·인증·관리자 화면·보고서·CSV/Excel을 확인했다. 사용자 입력을 번역하지 않고 option의 저장 값과 ISO 날짜를 유지한다. 미저장 초안·열린 다이얼로그·입력 중인 인증 화면에서는 언어 변경을 막는다.
- 3방향 병합은 필드·업무/인력/세부 작업 ID를 기준으로 처리한다. 같은 필드·삭제/수정·순서 경합은 명시적 선택을 요구하며, 선택 후에도 담당자·선행·계층·일정·완료 기록을 검증한다. 적용은 초안 단계이고 최종 저장은 기존 서버 권한과 revision 검사를 통과해야 한다.
- 500개 업무·20명·50개 상위 업무를 대상으로 5회 중앙값을 비교했다. 동일 로컬 Node 24 환경에서 HTML 생성은 변경 전 153.70ms → 변경 후 약 33ms, 검색은 46.77ms → 약 3ms였다. 모델 편집·일정 이동도 측정했다. 이는 네트워크·DB·브라우저 페인트를 제외한 측정이며 실제 브라우저에서도 500행 입력·검색·저장을 확인했다.
- 운영 알림은 014 마이그레이션의 영속 집계·설정 revision·원자 lease·시간당 제한·최대 3회 시도·확인 횟수 보존을 검증했다. 실제 TLS SMTP로 수신자별 발송, 주소 비공개, 반복 tick의 중복 발송 차단과 SMTP 실패 재귀 방지를 확인했다.
- 브라우저 시나리오: 가입 → 실제 로컬 인증 메일 → 비밀번호 설정 → 관리자 MFA 승인 → 승인 메일 → SMTP 실패 기록/알림 설정/확인 → 프로젝트/인력/업무 등록 → 완료 체크 → CSV/Excel 실제 다운로드 및 셀 검증 → 새로고침 후 완료 기록 유지.
- 별도 브라우저 시나리오로 동시 수정 비교/선택/저장과 서버 메모·완료일 보존, 영어 UI·원본 한국어 데이터·언어 설정 유지·미저장 전환 차단, 390px 모바일의 페이지 넘침·44px 이상 체크 영역·키보드 Space 완료, 500행 편집을 확인했다.
- 최종 단위/요청 182개, 실제 HTTP·TLS SMTP 14개, 별도 PostgreSQL 19개, 브라우저 5개로 총 220개를 검증했다. 실제 브라우저 오류도 검사한다. 포맷 검사·npm audit를 수행했다. CI에 브라우저 실행과 실패 trace/스크린샷 보관을 추가했다.
- 테스트는 일회용 메모리 저장소·loopback TLS SMTP·별도 _test DB만 사용했다. 운영 계정·MFA·메일을 테스트하지 않았다.
- 최종 CodeQL 대조에서 번역 함수의 공유 문자열 캐시를 통한 DOM/예외 문자열의 HTML 데이터 흐름 경고를 확인했다. 공유 캐시를 제거하고 번역을 호출별 순수 변환으로 바꿨다. 외부 문자열 호출 이후 고정 UI 문구 결과가 유지되는 회귀 검사도 추가했다.
