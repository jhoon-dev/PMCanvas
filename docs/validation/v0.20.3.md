## 새 회귀 검증

공통 조회 순서 검사에서 계정 전환·새 저장·더 최신인 프로젝트 동기화가 이전 응답을 무효화하는지 확인했습니다. 브라우저에서는 저장 후 내 업무 응답을 의도적으로 보류하고 다른 프로젝트를 최신 동기화한 다음 이전 응답을 전달해 화면이 덮어써지지 않는 것을 확인했습니다.

JSON 백업의 미확정 날짜·문자열을 원문으로 복구하고, 미확정 입력을 서버 데이터에서 분리하며, 잘못된 입력은 저장 전에 거절하는지 확인했습니다. 잘못된 업무/열·중복·값 형식·과도한 크기도 거절합니다. 브라우저에서 실제 JSON 다운로드 → 다시 불러오기 → 수정 → 저장을 검증하고, 최초 서버 생성이 503으로 실패한 경우에도 WBS에서 재시도하여 새 프로젝트로 저장하고 원본 프로젝트는 유지하는지 확인했습니다.

백업 덤프 생성 도중 실패 및 아카이브 검사 실패를 주입하여 불완전한 파일이 정상 덤프로 노출되거나 남지 않는 것을 확인했습니다. 하루 지난 자동 partial만 정리하고 최근 partial·수동 파일·키·완성 덤프를 보존합니다. 복원 점검 DB 생성 실패 시에는 검사된 덤프와 파일명을 보존하고 성공으로 기록하지 않습니다.

실제 DB 검증과 복구 검증은 전용 임시 DB에서 수행하고 생성한 DB만 정리했습니다. 브라우저 메일은 loopback 수신함을 사용했습니다. 운영 계정·외부 메일 수신자를 사용하지 않았습니다.
