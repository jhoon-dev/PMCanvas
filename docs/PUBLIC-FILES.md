# 공개 파일과 배포 검사

문서·메일/인증 예제·프록시 예제에는 `example.com`, `company.example`, `pm.test`, `localhost`처럼 예약된 주소를 사용합니다. IP 예제는 loopback 또는 문서 전용 대역으로 작성합니다. Entra 예제의 테넌트는 `YOUR-TENANT-ID`로 둡니다. 공식 문서 링크·표준 XML 네임스페이스 등은 검사 코드의 명시적인 공개 호스트 목록으로 구분합니다. 실제 운영 주소를 이 목록에 추가하지 마세요.

실제 접속 정보는 Git에서 제외되는 `.env`, `config/auth.json`, `config/mail.json`, `config/secrets/`에 설정합니다. 커밋 작성자 이메일은 이 검사 대상이 아닙니다.

## 공개 파일 검사

```sh
npm run public:check
```

Git 추적 파일과 `.gitignore`에 제외되지 않은 새 파일을 검사합니다. 제외된 운영 설정은 읽지 않습니다. 실수로 강제 추적한 실제 설정·키·인증서·덤프·백업·내장 저장소는 경로만으로 차단합니다. 하위 폴더의 config·secrets·certs에도 같은 규칙을 적용하며, 허용된 설정 예제는 접두 폴더가 있어도 내용을 검사합니다. 심볼릭 링크는 따라가지 않습니다.

문서와 예제에서 실제 호스트·이메일 도메인·IP·개인 홈 경로·비밀번호 직접 입력을 검사합니다. 개인 키와 알려진 GitHub/AWS 토큰 패턴은 소스 파일에서도 검사합니다. 빈 설정, 비밀 파일 경로, 환경 변수 참조는 허용하되 비밀번호의 실제 기본값은 허용하지 않습니다.

실패하면 파일·줄·규칙만 표시하고 발견한 비밀값 원문은 출력하지 않습니다. 원문은 로컬에서 확인해 실제 설정을 비공개 파일로 옮기고 공개 예제를 예약 주소로 바꾸세요. 임의의 비밀값을 모두 인식하는 검사는 아니므로 커밋 전에 diff도 확인합니다.

## 검증된 ZIP 생성

변경을 커밋해 작업 폴더가 깨끗한 상태에서 실행합니다.

```sh
npm run release
```

현재 커밋의 공개 경로 목록만 `git archive`로 포장합니다. 작업 폴더 전체를 압축하지 않습니다. ZIP 내부의 문서와 설정을 다시 검사한 뒤 `releases/PMCanvas-Server-v현재버전.zip`과 SHA-256을 출력합니다. 개인 설정·키·덤프·검증 스크린샷은 배포본에 포함하지 않습니다.

이미 만들어진 ZIP만 검사할 수도 있습니다.

```sh
npm run public:check -- --zip releases/PMCanvas-Server-v0.20.2.zip
```

ZIP은 개인 파일뿐 아니라 경로 탈출, Windows 파일명 충돌, 대소문자가 다른 중복 경로, 심볼릭 링크, 암호화, 지원하지 않는 압축 방식, 손상된 체크섬, 파일·전체 크기 초과도 거부합니다. CI는 공개 파일 검사와 ZIP 생성 검사를 모두 실행합니다. 검사한 파일이 커밋·배포되는 파일과 같도록 검사 후 추가 변경이 있으면 다시 검사하세요.

## 이미 공개된 정보

현재 파일의 삭제만으로 과거 Git 객체나 GitHub 캐시가 삭제되지는 않습니다. 이력 정리 이후 다른 PC에서도 새로 복제한 이력을 사용하고, 기존 복제본을 병합해 이전 이력을 다시 올리지 마세요. GitHub 캐시 처리는 [공식 삭제 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)에 따릅니다. 지원 문의 내용·접수 화면은 비공개 보관하고 저장소나 배포 ZIP에 넣지 않습니다.
