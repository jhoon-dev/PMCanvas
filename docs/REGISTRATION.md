# 회원가입 이메일 인증과 승인 · 0.17.0

관리자는 먼저 **계정 → 이메일 발송 설정**에서 SMTP를 저장하고 테스트 메일을 확인하세요. [메일 서버 설정](PASSWORD-RESET.md)은 인증 메일·관리자 승인 요청·승인 안내·비밀번호 재설정에 공통으로 사용합니다. SMTP 발송이 꺼져 있으면 신규 신청과 인증 메일 재발송은 접수하지 않습니다.

## 사용자 절차

1. 로그인 화면의 **회원가입**에서 이름과 이메일을 입력하고 **인증 메일 보내기**를 누릅니다.
2. 받은 편지함·스팸함에서 인증 메일을 확인합니다. 링크는 30분 동안 한 번만 사용할 수 있습니다.
3. 링크에서 본인의 이름과 12~256자 로그인 비밀번호·확인값을 입력하고 **이메일 인증 완료**를 누릅니다. 링크를 열기만 해서는 인증하지 않습니다.
4. 관리자 승인 후 승인 안내 메일을 받습니다. 인증 시 설정한 비밀번호로 로그인하세요.

메일이 도착하지 않거나 링크가 만료되면 회원가입 화면의 **이미 신청했나요? 인증 메일 다시 받기**를 사용하세요. 가장 최근에 발급한 링크만 유효합니다. 인증 전 로그인에 실패한 경우에도 재발송 링크를 제공합니다. 이미 인증한 가입 신청에는 다시 인증 메일을 보내지 않습니다.

메일 수신자가 이름과 비밀번호를 직접 확정하므로, 다른 사람이 이메일 주소를 먼저 신청해도 그 사람이 설정한 비밀번호로 계정을 사용할 수 없습니다. 직접 가입하지 않았다면 인증 메일을 무시하세요.

## 관리자 승인 요청과 안내 메일

관리자는 **계정 → 이메일 발송 설정 → 승인 요청 수신 이메일**에서 수신 주소를 저장합니다. 쉼표나 줄바꿈으로 최대 10개까지 입력할 수 있고 대소문자·중복 주소를 정리합니다. **비워두면 활성 관리자들의 등록 이메일**로 보냅니다. 기존 SMTP 설정을 사용하며 수신 주소만 바꾸어도 SMTP 비밀번호를 다시 입력할 필요는 없습니다.

저장하면 신규 인증과 이미 인증을 마친 승인 대기 신청에 적용합니다. 이전 주소의 대기·실패 작업을 중단하고 새 주소에 필요한 작업을 등록합니다. 같은 신청에 대해 같은 주소로 전달이 완료된 요청은 다시 보내지 않습니다. 이미 SMTP 발송 중인 메일은 이전 주소로 도착할 수 있습니다. 수신 주소를 바꾸어도 가입 승인 상태와 관리자 권한은 바뀌지 않습니다.

각 주소로 개별 발송합니다. 신청자 이름·이메일과 승인 대기 목록 링크를 포함하고 비밀번호·인증 토큰은 포함하지 않습니다. 미인증 신청에는 관리자 알림을 보내지 않습니다.

링크는 관리자 로그인·MFA 후 **계정 → 사용자 계정**을 엽니다. 신규 관리자 MFA 등록 시에는 복구 코드 보관 화면을 먼저 보여 주고, 닫으면 승인 목록을 엽니다. 링크 방문만으로 승인하거나 권한을 부여하지 않습니다.

**계정 → 사용자 계정**은 가입 신청을 먼저 표시합니다. **이메일 인증 대기** 계정에는 승인 버튼을 표시하지 않고 서버도 승인을 거절합니다. **이메일 인증 완료 · 승인 대기** 계정의 소속을 확인하고 **가입 승인**을 누르세요. 이메일 인증은 소속이나 업무상 접근 권한 확인을 대신하지 않습니다.

이메일 인증과 관리자별 승인 요청 작업을 같은 DB 트랜잭션에 보관합니다. 인증 링크를 재사용해도 요청 작업을 중복 생성하지 않습니다. 관리자별 전달 결과를 따로 보관해 실패한 수신자만 재시도하며, 기본 관리자 주소 모드에서는 발송 시 관리자 활성·권한을 다시 확인하며, 두 모드 모두 신청 대기 상태를 확인합니다. 이미 승인한 신청의 미발송 요청은 더 보내지 않습니다.

승인과 신청자 안내 메일 작업도 같은 DB 트랜잭션에 보관합니다. 발송 실패로 승인을 취소하지 않습니다. 백그라운드 작업은 30초마다 확인하며 실패 후 최소 1분 간격으로 총 3회 시도합니다. 서버 재시작 후에도 남은 승인 알림을 처리합니다. 작업의 2분 임대가 끝나면 다른 인스턴스에서 회수할 수 있습니다. 정상적으로 전달한 안내는 반복 승인·재활성화 시 다시 보내지 않습니다.

계정 목록을 다시 열면 **발송 대기 / 발송 중 / SMTP 전달 완료 / 발송 실패** 상태를 확인할 수 있습니다. 관리자 승인 요청의 상태도 인증된 대기 계정에 표시합니다. 최종 실패 시 SMTP 설정을 수정하고 해당 계정의 **실패한 메일 다시 보내기**(관리자 요청) 또는 **다시 보내기**(신청자 안내)를 누르세요. 이미 전달된 관리자 요청은 다시 보내지 않습니다. 비활성화된 계정에는 발송하지 않습니다. SMTP 수락 직후 프로세스가 중단되는 경우처럼 전달 결과를 확정할 수 없을 때는 재시도로 같은 메일이 중복 도착할 수 있습니다. SMTP 전달 완료가 받은 편지함 도착을 보장하지는 않습니다.

승인해도 기존 프로젝트의 공유 권한은 자동 부여하지 않습니다. 소유자가 **프로젝트 관리 → 공유**에서 추가해야 합니다. 관리자 직접 생성 계정과 SSO·SAML·AD의 계정 정책은 종전 방식을 유지하며 이 가입 인증 절차를 강제하지 않습니다.

## 설정

.env 또는 프로세스 환경변수를 변경하고 앱을 재기동합니다. compose.yml과 compose.external.yml에 모두 적용됩니다.

| 설정 | 기본값 | 동작 |
|---|---|---|
| REGISTRATION_MODE | approval | 이메일 인증 후 관리자 승인 |
| REGISTRATION_MODE=disabled | | 신규 신청·인증 재발송 차단, 회원가입 링크 숨김 |
| REGISTRATION_DOMAINS | 빈 값 | 모든 이메일로 신청 가능. company.com,example.org로 설정하면 정확한 도메인만 허용. 하위 도메인은 별도 등록 |

발송 중지나 신규 가입 중지 후에도 이미 받은 링크는 만료 전까지 인증할 수 있습니다.

## 보안과 업데이트

- 인증 토큰은 암호학적 난수 256비트로 생성하고 DB에 SHA-256 해시만 저장합니다. 사용자·현재 자격 증명·만료 시각에 묶고 행 잠금으로 한 번만 소비합니다. 인증 후에도 비활성 승인 대기 상태이며 세션을 발급하지 않습니다.
- 링크는 PUBLIC_ORIGIN·BASE_PATH로 만들고 토큰은 URL fragment에 넣습니다. 화면 진입 시 fragment를 제거하며 링크·비밀번호를 로그/API 응답에 포함하지 않습니다. Referrer-Policy는 no-referrer입니다.
- 기존 로컬·관리자·SSO 계정과 중복되면 같은 접수 응답을 반환하며 정보를 덮어쓰지 않습니다. 재발송은 미인증 가입 대기 계정에만 적용하며 존재 여부와 관계없이 같은 응답을 보냅니다. 비동기 발송 대기열은 제한됩니다.
- 신청·재발송은 이메일별 합산 3회/시간, 각각 사용자 IP별 10회/15분·전체 100회/시간으로 제한합니다. 인증 완료는 IP별 20회/15분, 전체 200회/15분, 토큰별 5회/15분입니다. Origin·JSON 검사와 비밀번호 확인을 적용합니다. 프록시 배포에는 TRUSTED_PROXIES가 필요합니다.
- 승인과 안내 재발송은 관리자 세션·CSRF 검사가 필요합니다. 안내 재요청은 계정별 3회/시간·전체 100회/시간입니다. 인증·발송·승인·실패·재시도를 보안 감사 로그에 기록합니다.

011_review_recipients 마이그레이션은 시작 시 자동 적용됩니다. 기존 발송 기록과 기본 수신 방식을 유지하며, 승인 대기 신청의 수신 작업은 저장된 설정에 맞추어 갱신합니다. 여러 앱 인스턴스를 운영한다면 함께 업데이트하세요. 기존 활성 계정은 그대로 사용할 수 있습니다. 이메일 인증 도입 전 버전의 가입 승인 대기 계정은 인증 메일 재발송으로 인증해야 승인할 수 있습니다. 업데이트 전 **npm run backup**으로 DB를 백업하세요.

설계 참고: [OWASP 일회용 이메일 토큰 지침](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
