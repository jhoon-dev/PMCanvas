# 회원가입과 승인 · 0.12.0

로그인 화면의 **처음이신가요? 회원가입**에서 이름·이메일·12자 이상 비밀번호와 확인을 입력합니다. 신청을 접수하면 관리자 승인 대기 안내를 보여 줍니다. **로그인으로 돌아가기**는 신청 이메일을 채우고 비밀번호에 초점을 둡니다.

관리자는 **계정 → 사용자 계정**에서 대기 계정을 먼저 확인할 수 있습니다. 이메일과 소속을 직접 확인한 뒤 **가입 승인**을 누르세요. 승인 전에는 비밀번호가 맞아도 로그인할 수 없으며 세션과 프로젝트 접근 권한을 발급하지 않습니다. 승인해도 기존 프로젝트의 공유 권한은 자동 부여하지 않습니다. 소유자가 **프로젝트 관리 → 공유**에서 추가해야 합니다.

## 설정

.env 또는 프로세스 환경변수를 변경하고 앱을 재기동합니다. compose.yml과 compose.external.yml에 모두 적용됩니다.

| 설정 | 기본값 | 동작 |
|---|---|---|
| REGISTRATION_MODE | approval | 가입 신청과 관리자 승인 사용 |
| REGISTRATION_MODE=disabled | | 회원가입 링크를 숨기고 API도 차단. SSO 전용 조직에서 사용 |
| REGISTRATION_DOMAINS | 빈 값 | 비어 있으면 모든 이메일로 신청 가능. company.com,example.org처럼 입력하면 정확한 도메인만 허용. 하위 도메인은 별도 등록 |

도메인 제한은 이메일 소유 확인을 대신하지 않습니다. 현재 SMTP·이메일 인증·승인 알림 메일을 제공하지 않으므로 관리자가 직접 확인하고 승인 결과를 전달합니다. SSO·SAML·AD의 기존 계정 생성 정책은 각 인증 연결의 설정을 사용합니다.

## 계정 보호

- 가입 요청에서 관리자·활성 상태를 보내도 일반 승인 대기 계정만 생성합니다. DB 제약도 대기 계정의 활성·관리자 상태를 막습니다.
- 기존 로컬·관리자·SSO 이메일과 중복되면 같은 접수 응답을 반환하며 기존 이름·비밀번호·외부 연결을 바꾸지 않습니다. 관리자 목록에 기존 계정만 있다면 해당 계정의 로그인 방식을 확인하세요.
- 비밀번호 확인·12~256자 제한, scrypt-v2 해시, 동일 Origin·JSON 요청 검사를 적용합니다. 비밀번호를 감사 로그와 응답에 포함하지 않습니다.
- 이메일별 3회/시간, 검증된 사용자 IP별 10회/15분, 전체 100회/시간으로 요청을 제한합니다. 전체 한도는 가입 경로에만 적용하며 로그인 한도와 분리됩니다. 프록시 배포는 TRUSTED_PROXIES를 설정하세요.
- 가입 신청과 관리자의 계정 활성 변경을 보안 감사 로그에 기록합니다. 관리자만 승인할 수 있고 승인 요청에는 세션과 CSRF 토큰이 필요합니다.

006_registration 마이그레이션은 시작 시 자동 적용됩니다. 기존 사용자는 승인 대기 상태로 바뀌지 않습니다. 업데이트 전 npm run backup으로 DB를 백업하세요.
