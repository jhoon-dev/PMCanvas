# Android 에뮬레이터 검증 시도 — 2026-10-30

## 결과

**주요 기능 검증은 미완료입니다.** 설치한 APK의 WebView에 연결해 기능 시나리오를 실행할 수 있는 안정적인 Android 실행 상태에 도달하지 못했습니다. 앱 결함 여부도 이 결과만으로 판단하지 않습니다.

| 확인 항목                                      | 결과                                                                        |
| ---------------------------------------------- | --------------------------------------------------------------------------- |
| APK 설치                                       | Android 14 가상기기에서 성공                                                |
| 네이티브 실행 요청                             | `dev.jhoon.pmcanvas/.MainActivity`에 대한 `am start -W`가 `Status: ok` 반환 |
| APK의 앱 ID·버전·진입 액티비티                 | `dev.jhoon.pmcanvas`, `0.1.0`, `MainActivity` 확인                          |
| 앱 WebView 연결                                | 제한 시간 내 연결하지 못함                                                  |
| 프로젝트·인력·업무 편집                        | 미검증                                                                      |
| 완료 체크·공수 가중 진척률·실행 취소·다시 실행 | 미검증                                                                      |
| 강제 종료 후 데이터 복원·Android 뒤로 가기     | 미검증                                                                      |
| 네이티브 공유 시트·프로젝트 파일 가져오기      | 미검증                                                                      |

기존 브라우저 테스트 결과와 이 네이티브 에뮬레이터 결과는 구분합니다. 브라우저 테스트 통과를 위 항목의 통과로 계산하지 않습니다.

## 환경과 관찰

- Windows의 Android Emulator 37.1.11, WHPX, x86_64 시스템 이미지를 사용했습니다.
- 기존 Android 14 가상기기에서는 `DeadSystemException`, 시스템 서비스 재시작, `System UI isn't responding`이 관찰됐습니다.
- Android 13 테스트 전용 가상기기를 추가해 720×1280 화면, 소프트웨어 그래픽 렌더링과 별도 데이터 폴더로 재시도했습니다. 부팅 완료를 기다리는 단계에서 제한 시간을 넘었습니다. 시스템 앱의 초기 `dex2oat` 검증도 오래 지속됐습니다.
- 창이 있는 실행에서 호스트 OpenGL 로딩 오류가 관찰돼 창 없는 실행과 Vulkan 비활성화도 시도했습니다. 이 실행에서도 주요 기능 검증 단계에 도달하지 못했습니다.
- 시스템 이미지·가상기기 상태와 호스트 가상화·그래픽 환경 중 어느 것이 주원인인지는 확정하지 않았습니다.

앱 소스는 이 문제 때문에 변경하지 않았습니다. 진단용 프로세스는 정리했으며, 기존 가상기기의 데이터를 초기화하지 않았습니다.

## 다시 실행하기

정상 부팅이 끝난 테스트용 Android 에뮬레이터와 빌드한 개발용 APK가 필요합니다. 실제 사용자 기기를 자동 선택하지 않도록 스크립트는 에뮬레이터만 대상으로 합니다.

```sh
cd mobile
npm ci
npx playwright install android
npm run android:apk
npm run test:android
```

에뮬레이터가 여러 대이면 `PM_ANDROID_SERIAL` 환경 변수로 하나를 지정합니다. PowerShell 예시:

```powershell
$env:PM_ANDROID_SERIAL = 'emulator-5558'
npm run test:android
```

`PM_ANDROID_APK`로 다른 APK 경로를 지정할 수 있습니다. 초기 부팅 대기 시간의 기본값은 180000ms이며 `PM_ANDROID_BOOT_TIMEOUT_MS`로 조절할 수 있습니다.

스크립트는 APK를 설치하고 별도의 이름을 가진 검증용 프로젝트를 만듭니다. 프로젝트·인력·업무 편집, 완료 체크, 검색, 실행 취소·다시 실행, 네트워크 요청을 오프라인으로 전환한 상태의 편집, Android 뒤로 가기, 강제 종료 후 복원, 공유 시트, 내보낸 파일과 CSV 내용, Android 파일 선택기를 통한 가져오기를 검사하도록 작성했습니다. **이 시도에서는 해당 기능 시나리오를 끝까지 검증하지 못했으므로 스크립트 자체의 전체 실행 검증도 남아 있습니다.**

실행별 결과 JSON과 스크린샷은 `mobile/test-results/android-native/`에 저장하며 소스에 포함하지 않습니다. 테스트 전용 가상기기의 시스템 로그와 초기화 파일은 저장소의 `test-results/android-emulator/`에 남겼습니다.
