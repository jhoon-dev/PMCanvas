# 검증 결과 · 2026-10-26 · 0.16.0

- 단위·요청 처리 120개, 실제 HTTP·TLS SMTP 12개, 실제 PostgreSQL 12개: 합계 144개 통과.
- 이메일 인증과 활성 관리자별 승인 요청 작업을 원자적으로 보관. 미인증 신청 무발송, 인증 링크 재사용·동시 소비 시 관리자 알림 중복 생성 금지 확인.
- 모든 활성 관리자에게 개별 수신자로 전달, 일반 사용자·비활성 관리자 제외, 발송 시 관리자 권한·활성 상태와 승인 대기 여부 재검사.
- 관리자별 실패만 3회 시도, 최종 실패 후 관리자·CSRF·Origin 검사를 거쳐 실패한 수신자만 재발송. 다른 인스턴스의 작업 회수와 신청자 승인 안내 발송 기능 유지.
- 실제 TLS SMTP에서 신청자 인증 메일 → 관리자 승인 요청(신청자 이름·이메일·목록 링크) → 승인 후 신청자 안내 순서 확인. 비밀번호·인증 토큰·추가 수신자 정보가 관리자 메일에 포함되지 않음.
- 010 마이그레이션 반복 적용, 기존 발송 완료 기록 보존, 이미 인증한 대기 신청만 활성 관리자에게 작업 등록, 복합 키 중복 방지, 사용자 목록 중복 행 없음 확인.
- 브라우저에서 승인 요청 링크 → 관리자 로그인·MFA 등록 → 복구 코드 보관 → 승인 대기 목록 자동 열기 확인. 기존 관리자 로그인 상태의 링크와 일반 사용자 접근 차단도 확인.
- 링크 방문만으로 승인되지 않으며 승인 전 로그인 차단. 실제 승인 후 신청자 안내 메일 1통과 로그인 성공 확인. 390px 모바일 가로 넘침 없음.
- 운영 계정/MFA·운영 SMTP·실제 외부 수신자는 테스트에 사용하지 않음. 별도 메모리 DB와 loopback TLS SMTP, 전용 PostgreSQL DB 사용.
- 운영 DB 백업 후 010 마이그레이션·알림 수신자 제약·앱/DB healthcheck 정상. 기존 SMTP 발송 중지 상태 유지. 전용 PostgreSQL 테스트 DB·임시 테스트 소스 정리. npm audit 취약점 0개.
