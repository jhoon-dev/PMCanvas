## 회귀 범위

백업의 DB 생성 단계 표시 이름을 영어로 바꾼 뒤 실패를 주입해 복원 알림 종류가 유지되는 것을 확인했습니다. 덤프·파일 검사 실패는 백업, 점검 DB 정리 실패는 복원으로 분류합니다. 기존 실행 메시지·partial 처리·보존·lease 동작을 유지했습니다.

오류 코드·SMTP 명령·상태를 조합한 분류 검증에는 연결·DNS·시간 초과·TLS 인증서·인증 실패, 영구 사서함 거부, 릴레이 정책·발신자·일시 오류·원인 불명의 거부를 포함했습니다. SMTP 원문·수신 주소·비밀번호는 진단 기록에 남지 않습니다. 운영 알림 메일 실패의 재귀 알림 방지도 유지했습니다.

loopback TLS SMTP 서버가 실제로 영구 사서함 거부와 릴레이 거부를 반환하도록 하고, 잘못된 비밀번호·인증서 호스트 이름·닫힌 포트도 각각 확인했습니다. 수신자 거부는 집계·감사 기록만 남고 나머지 네 실패는 운영 알림에 반영됩니다. 외부 수신자에게 보내지 않았습니다.

실제 PostgreSQL에서 동시 인증 오류 12개의 집계·알림 횟수가 보존되고 수신자 거부는 알림에서 제외되는 것을 확인했습니다. 감사 기록 저장에 실패를 주입했을 때 집계와 운영 알림도 함께 롤백되는지 확인했습니다. 잘못된 분류·발송 종류·상태 코드 입력은 거절합니다.

브라우저에서는 기존 가입·인증·승인·업무·완료·Excel·동시 수정·한/영·모바일·500개 업무 흐름을 유지하고, 관리자 운영 알림의 메일 실패 상세에서 연결 오류가 표시되는 것을 확인했습니다. 실제 복구 검증도 로그인·MFA·메일·업무 기록·공유 권한을 확인했습니다. 운영 데이터나 자격 증명을 테스트에 사용하지 않았습니다.
