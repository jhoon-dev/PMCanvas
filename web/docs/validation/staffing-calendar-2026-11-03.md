# 투입 계획 연계 · 계층 계산 성능 검증

2026-11-03 Windows x64, Node.js v24.16.0에서 검증했습니다.

## 변경 내용

- 투입 계획이 없는 프로젝트에서 `remove-assignment`를 호출해도 오류가 발생하지 않습니다. 없는 항목의 반복 삭제도 허용하며 원본 프로젝트를 변경하지 않습니다.
- 날짜별 가용시간 계산을 예측·과부하 경고·월별 계획 M/M에 공통 적용했습니다. 기간 계획이 없는 인력은 기본 투입률을 사용하고, 기간 계획이 있는 인력은 해당 날짜의 계획 투입률 합계를 사용합니다. 기간 밖·공백은 0%이며 마지막 기간 삭제 시 기본 투입률로 복귀합니다.
- 기간별 투입률은 기본 투입률을 대체합니다. 두 값을 곱하지 않습니다. M/M 환산 기준은 보고 단위만 변경하며 예상일·가용시간에는 영향을 주지 않습니다.
- 인력 화면과 대시보드의 투입률 합계, WBS CSV의 투입률도 보고 기준일의 적용 투입률을 사용합니다. 관리 화면·도움말·문서에 적용 규칙을 안내했습니다.
- 가용시간이 없는 기간은 예측에서 건너뛰고, 등록된 기간 내 가용시간이 부족하면 완료일을 계산 대기로 표시합니다. 부분 배정한 마지막 날짜를 확정 완료일로 표시하지 않습니다. 이후 업무·마일스톤에도 계산 대기를 전달합니다.
- 계층 인덱스를 계산·렌더링 단위로 만들어 재사용합니다. 예상일의 요약 집계, 기준 계획, WBS·대시보드·데스크톱 표와 간트, CSV·Excel 출력에서 반복 탐색을 줄였습니다. 전역 객체 캐시는 사용하지 않으며 다음 계산에서는 같은 프로젝트 객체의 수정도 반영합니다.

WBS 계획 날짜·공수·계획 진척률과 자원 평준화를 제외한 CPM의 정의는 유지합니다. 가용시간 변경은 예측과 과부하 점검에 적용하며 계획 날짜를 자동으로 변경하지 않습니다.

## 기능 검증

- 웹 단위·요청 테스트 **282개 통과**, 실패·건너뜀 0개.
- 데스크톱 테스트 **103개 통과**, 실패 0개, 플랫폼 전용 **3개 건너뜀**. 렌더러와 업데이트 화면 검증도 통과했습니다.
- 모바일 모델·저장소 테스트 **10개 통과**, Android Chromium·iPhone WebKit 브라우저 시나리오 **8개 통과**, 프로덕션 빌드 통과.
- 웹 브라우저에서 투입 계획 저장·재조회 → M/M·예상일·인력별 가용시간 반영 → 마지막 기간 삭제 후 복귀를 확인했습니다. 기존 PM 관리·발행 사본·모바일 내 업무 시나리오 3개도 통과했습니다.
- 실제 PostgreSQL **18.6** 통합 테스트 **23개 통과**, 덤프·별도 DB 복원 테스트 **1개 통과**, 실패·건너뜀 0개. 투입률을 25%로 저장하고 새로 읽었을 때 M/M과 가용시간 부족에 따른 계산 대기가 반영되는 검증을 추가했습니다. 운영 DB에 연결하지 않았고 검증용 서버는 종료했습니다.
- 변경 파일의 Prettier 검사와 `git diff --check` 통과.

주요 회귀 조건은 다음과 같습니다.

| 조건 | 확인 결과 |
| --- | --- |
| 40h 업무, 2026-11-02 시작, 25% 기간 계획, 하루 8h | 2026-11-27 완료 예상, 계획 부하 8h 대비 가용시간 2h 경고 |
| 기본 투입률 50% + 기간별 25% | 적용 투입률 25%, 12.5%로 곱하지 않음 |
| 겹치는 25%·50% 기간 | 겹치는 날짜는 75%, 시작·종료 경계별 경고 분리 |
| 기간 사이 공백·주말·휴무일 | 작업 배정 제외, 이후 유효한 투입일부터 재개 |
| 같은 인력의 병행 업무 | 날짜별 가용시간 중복 사용 방지 |
| 등록한 투입 계획의 가용시간 부족 | 완료일과 후속 예상일 계산 대기 |
| 10년 계산 범위 이후에만 투입 계획이 존재 | 범위를 넘어 날짜를 배정하지 않음 |
| 계획이 없는 인력·빈 계획 목록·마지막 기간 삭제 | 기본 투입률 사용 |
| 소수 투입률 기간 종료 | 공백·기간 밖에 부동소수점 잔여 가용시간이 생기지 않음 |
| 완료한 업무 | 실제 완료일 유지, 투입 계획으로 재배치하지 않음 |
| 중첩·빈 요약·임의 행 순서·편집 후 재계산 | 공수·일정·선행 관계 집계 유지 |

## 성능 측정

`web`에서 `node scripts/benchmark.mjs`로 재실행할 수 있습니다. 5회 측정의 중앙값이며 기기·동시 실행 작업에 따라 달라집니다.

| 측정 | 현재 중앙값 |
| --- | ---: |
| 상위 50개·실제 업무 200개·인력 15명 예상 계산 | 17.13ms |
| 같은 프로젝트의 요약 집계 | 0.44ms |
| 기존 500개 업무 화면 렌더링 | 70.32ms |
| 기존 500개 업무 필터 | 4.32ms |

작업 전 같은 규모의 예상 계산을 별도 측정한 값은 7회 중앙값 37.4ms였습니다. 절대 실행시간을 보장하는 테스트 임계값으로 사용하지 않으며, 브라우저와 휴대폰의 성능은 별도 환경에 따라 달라집니다.
