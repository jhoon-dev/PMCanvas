# 검증 결과 · 2026-10-26 · 0.19.1

- 실제로 보이는 로컬 데모 탭에서 이메일 가입 신청 → TLS SMTP 인증 메일 → 이름·비밀번호 설정과 인증 → 관리자 MFA → 프로젝트 초대를 포함한 승인 → 신규 계정 로그인 → 표에서 업무명·담당자·종료일 입력과 저장 → 내 업무 카드 → 완료 체크를 수행했다.
- 승인 요청과 가입 승인 안내 메일을 로컬 메일함에서 확인했다. 완료일 2026-10-26, 업무 진척률 100%가 새로고침 후에도 유지됨을 확인했다. 운영 계정·DB·SMTP는 사용하지 않았다.
- 단위·요청 처리 테스트 142개, 실제 HTTP·TLS SMTP 테스트 13개, 실제 PostgreSQL 테스트 18개: 총 173개 통과. 포맷 검사 통과, 의존성 설치 점검의 알려진 취약점 0개.
- 백업 이미지에 migrations 폴더를 포함했다. 복원 점검에서 파일로 발견한 버전 목록과 복원 DB의 목록을 정확하게 비교한다. 개수만 같고 중간 번호가 빠진 경우, 최신 버전 누락, 더 새로운 버전을 거절하는 회귀 테스트를 추가했다.
- 별도 PostgreSQL 테스트 DB와 Linux UID/GID 1001의 백업 컨테이너로 실제 덤프·복원 성공을 확인했다. 덤프 47,975바이트, verified=true, 키 식별자 64자. 동일 테스트 DB의 013 적용 기록을 삭제한 뒤 재실행하자 ‘복원 데이터 확인’ 실패, verified=false로 기록됐으며 점검용 임시 DB는 남지 않았다.
- 기존 키 사본 이동 시 실제 recovery-keys 경로와 프로젝트 밖의 별도 보관 장소로 옮기라는 메시지를 추가했다. 전체 프로젝트를 백업하면 덤프와 키가 함께 포함될 수 있다는 점도 표시한다.
- `npm run demo`는 개발 의존성을 사용하는 명시적 로컬 체험 명령이다. 운영 .env를 로드하지 않고 메모리 저장소와 loopback TLS SMTP를 사용한다. 한 시간 뒤 종료되며 재실행 시 초기화된다.
- app.js의 WBS·대시보드 추가 분리는 유지보수 후속 작업으로 남겼다. 이번 수정에서는 해당 화면의 동작과 계산 로직을 변경하지 않았다.
