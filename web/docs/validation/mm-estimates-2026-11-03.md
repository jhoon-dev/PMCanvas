# M/M 추정값 표시 · 포맷 수정

2026-11-03 Windows에서 검증했습니다. 클로드코드의 마지막 두 지적에 대한 반영 내용입니다.

## 반영 내용

- `mobile/index.html`에 Prettier를 적용했습니다. 저장소 루트의 `npm run format:check` 전체 검사가 통과했습니다.
- 월별 M/M 표에 **집계 기준** 열을 추가했습니다. 인력별로 **기간별 계획** 또는 **기본 투입률로 추정**을 표시합니다.
- 합계에 기본 투입률 추정분이 있으면 **추정값 포함** 표시와 추정 시간·M/M을 함께 안내합니다. 추정 기여분이 없으면 해당 안내는 표시하지 않습니다.
- 투입 기간이 없는 인력은 업무 기간 밖에도 기본 투입률로 집계된다는 점과, 그 값이 실제 투입 실적이나 등록한 기간별 계획을 뜻하지 않는다는 점을 명시했습니다. 한국어·영어에 모두 적용했습니다.
- 등록한 기간별 계획의 조회 월 결과가 0이어도 집계 기준은 기간별 계획으로 유지합니다. 마지막 기간을 삭제하면 기본 투입률 추정으로 바뀝니다.

업무 기간 밖의 1.10 M/M을 0으로 바꾸는 대신, 리뷰에서 제안한 집계 근거 표시 방법을 선택했습니다. 계획 종료일을 넘는 업무의 예상일 계산에는 종료일 이후 가용시간도 필요하므로 공통 가용시간 계산을 업무 기간으로 제한하지 않았습니다. 예측·과부하·M/M의 계산 규칙은 유지합니다.

`monthlyPlan()`의 계산 결과에 인력별 `basis`와 합계의 `estimatedHours`, `estimatedMM`을 추가했습니다. 이는 조회 결과이며 프로젝트 저장 데이터·파일 버전·DB 스키마를 변경하지 않습니다.

- 웹 브라우저: 관련 **2개 시나리오 통과**. 업무 기간 밖 월 조회, 마지막 기간 삭제 후 추정 표시 전환, 합계 안내와 기존 PM 관리·모바일 화면을 확인했습니다.
- 모바일 프로덕션 빌드 통과.

대표 재현은 2026년 11월 업무를 가진 프로젝트의 2027년 6월 조회입니다. 기간 계획이 11월에만 있는 A는 0.00 M/M·기간별 계획, 기간 계획이 없는 B는 1.10 M/M·기본 투입률로 추정으로 구분합니다. 합계의 추정분은 176h·1.10 M/M입니다. 환산 기준 변경, 마지막 기간 삭제, 이름 HTML 이스케이프, 영어 표시도 검증했습니다.
