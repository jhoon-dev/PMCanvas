# 예측 안정화·공휴일 일치·문서 정리

2026-11-08, Windows x64·Node.js v24.16.0에서 검증했습니다. 제품 버전은 웹 0.21.9·데스크톱 1.9.0·모바일 0.3.1이며, 이 기록은 이번 변경의 검증 범위입니다.

## 변경

- 소량의 완료 체크가 전체 남은 일정에 과도하게 반영되지 않도록 계획 속도와 관측 속도를 혼합합니다. 관측 기간·완료 날짜 수·완료 공수가 늘면 실적 비중이 커집니다. 적용 규칙과 한계는 [공통 엔진 안내](../../../shared/README.md#예상-완료일)에 남겼습니다.
- 웹·데스크톱·모바일 현황에 기록 부족과 혼합 추정을 표시합니다. 인력 화면은 원래 관측 비율과 예측 적용 비율을 함께 보여줍니다. CSV·Excel에도 혼합 추정 방법을 표시하고 한국어·영어 문구와 웹 계산 도움말을 갱신했습니다.
- 자동 한국 공휴일과 수동 휴일을 합친 달력을 계산과 일정 점검에 사용합니다. 휴일·주말만 있는 일반 업무는 저장을 허용하고 업무명·날짜·수정 안내가 있는 경고로 표시합니다. 공휴일 갱신이나 서버의 기존 값 재검증이 파일 열기·복구·수정을 막지 않습니다. 웹 현황의 계획 대비 지연 일수도 같은 달력을 사용합니다.
- 백업 작업용 이미지 정의를 `web/backup-worker.Dockerfile`로 변경하고 기본·외부 DB Compose, CI, 배포 목록을 함께 갱신했습니다. 파일 내용은 이전 이미지 정의와 동일합니다. 공개 파일 검사에서는 Dockerfile 확장자를 파일명으로 인식하고 실제 URL의 호스트 검사는 유지합니다.
- README에 짧은 제품 소개와 기존 가상 프로젝트 스크린샷을 추가하고 [제품 범위](../../../docs/product-scope.md)를 명시했습니다. 과거 검증 파일·링크는 보존하고 색인을 최근 변경과 과거 버전으로 나눴습니다.

## 완료한 검사

- 웹 단위·요청 테스트 303개 통과. 공개 파일 검사와 기준 계획 곡선 회귀 2개는 이 안에 포함됩니다.
- 데스크톱 131개 통과, 플랫폼 전용 3개 건너뜀. 휴일 전용 파일 열기·미저장 복구와 공휴일 갱신 후 작업 공간 재시작·날짜 수정·저장을 확인했습니다. 해당 문서·공휴일 파일의 집중 검사도 24개 통과했습니다.
- 격리된 PostgreSQL 18 테스트 DB의 통합 검사 24개 통과. 새 회귀는 SQL로 기존 일정에 휴일 날짜를 직접 저장한 뒤, 정상 날짜의 수정본을 HTTP로 저장하여 `updateProject`의 `cleanProject(before)` 재검증까지 확인합니다. 휴일 날짜를 그대로 둔 일반 편집도 저장하고 재조회하며, 잘못된 날짜는 400으로 거부하는지 확인합니다. 전용 컨테이너는 검사 후 제거했습니다.
- 모바일 모델·저장소 테스트 18개 통과, 프로덕션 빌드 통과.
- 초기 변경 시 모바일 브라우저 Android Chromium·iPhone/iPad WebKit의 48개 시나리오를 확인했습니다. 최초 45개 통과, 일요일 하루짜리 Excel 입력을 사용하던 동일 시나리오의 3기기 실패는 다음 근무일 입력으로 수정한 뒤 해당 3개를 재실행해 모두 통과했습니다. 휴일 정책 보완 후에는 아래 신규 회귀 시나리오를 실행했습니다.
- 초기 웹 Chromium 브라우저 3개 통과: 혼합 예측·인력 표시·390px 넘침 확인, 영어 UI, 투입 계획 저장·재조회. 휴일 정책을 경고로 바꾼 후의 화면 검사는 아래 호환성 보완 결과에 기록합니다.
- 데스크톱 렌더러 검증 통과: 편집·보고서·WBS·일정·이력·필터·저장·재조회·데이터 보존.
- 기본·외부 DB Compose 구성 검사와 새 파일명의 백업 Docker 이미지 빌드 통과. 배포 목록의 모든 경로 존재, 이전 Dockerfile과 내용 동일, 변경 문서의 상대 링크를 확인했습니다.

## 휴일 일정 호환성 보완 결과

근무일이 없는 업무를 검증에서 거부하던 초기 수정은 철회했습니다. 서버는 수정본뿐 아니라 DB의 기존 프로젝트도 다시 검증하므로, 정상 날짜로 고친 수정본까지 저장이 막히는 문제가 있었습니다. 파일 열기·문서 복구·작업 공간 복구도 같은 검증을 사용합니다. 달력 변경에 따른 경고와 데이터 형식 검증을 분리했습니다.

- 웹 브라우저 2개 통과: 휴일 전용 프로젝트 생성·경고 표시·날짜 수정·저장 응답 200·새 조회에서 수정 날짜 유지, 기존 과부하 점검 회귀. 혼합 예측·관측 비율·좁은 화면도 함께 확인했습니다.
- 모바일 브라우저 3개 통과: Android·iPhone·iPad에서 휴일 전용 프로젝트 가져오기 → 업무명·날짜 경고 → 날짜 수정 → 저장 완료 → 재시작 후 수정 날짜와 공수 보존.
- 경고 개수·업무명 HTML 이스케이프·한국어/영어 문구, 요약·마일스톤 제외, 수동 휴일·자동 공휴일·주말, 공휴일 업데이트 전후 경고 재계산을 모델과 렌더링 검사로 확인했습니다.
- PostgreSQL의 기존 프로젝트 재검증은 메모리 저장소로 대체하지 않고, 별도 컨테이너의 실제 SQL 저장값과 HTTP 수정을 통해 확인했습니다. 문서 복구와 깨끗한/미저장 작업 공간 복구도 실제 파일로 확인했습니다.
- 주간보고의 기준 계획 곡선도 엔진 `planned()`를 사용합니다. 공휴일·수동 휴일·주말 전용 업무와 혼합 일정에서 현재/기준 곡선이 종료 시점에 100%에 도달하고 요약·마일스톤 공수가 중복되지 않는 회귀 2개를 추가했습니다. 수정 전 실패와 수정 후 관리 기능 검사 14개 통과를 확인했습니다. 기존 발행 보고서 사본은 보존합니다.
- 기준 곡선 수정 후 웹 303개·데스크톱 문서/보고서 23개·모바일 18개, 전체 포맷·공개 파일 검사를 통과했습니다.

## 범위와 한계

모바일 브라우저는 데스크톱 브라우저의 기기 에뮬레이션이며 실제 네이티브 앱 검증을 대신하지 않습니다. 실행 로그와 스크린샷은 Git에서 제외되는 `test-results/`와 제품별 `test-results/`에 보관했습니다.

혼합 비중은 통계적 신뢰도가 아닌 안정화 규칙이며, 드문 체크로 실제 지연이 과소 반영될 수 있습니다. 진척률과 관측 속도를 함께 확인해야 합니다. 근무일이 없는 업무는 날짜를 자동 변경하지 않고 경고합니다. 계획 공수는 계획 종료일부터 반영하고 예상 속도·CPM 기간은 최소 1일로 처리하되 실제 예상 작업 배정에서는 휴일을 제외합니다.

실제 PostgreSQL 백업·복원, Store 서명·설치·제출, 실기기 Android/iOS 검사는 이번에 실행하지 않았습니다. 백업 이미지는 빌드했으며 운영 서비스를 기동하거나 운영 DB에 연결하지 않았습니다. 공개 ZIP 생성은 커밋된 소스가 필요하므로 실행하지 않았습니다.
