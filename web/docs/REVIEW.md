# 코드 리뷰 대조와 반영 · 0.19.0

## 0.21.3 추가 개선 · 2026-10-28

계층형 WBS에서 상위 업무를 위로 옮기면 원래 배열에서는 직전 하위 업무와 자리만 바뀌어 화면의 형제 순서는 그대로 남는 경우를 수정했습니다. 이제 같은 상위 업무 아래의 형제 순서를 바꾸고 하위 묶음을 함께 옮깁니다. 상위와 하위가 동시에 선택되면 하위 내부 순서는 유지합니다. ID·담당자·선행 관계·완료 기록·기준 계획을 바꾸지 않으며 선택이 경계에 있으면 불필요한 변경을 만들지 않습니다. 웹과 데스크톱이 사용하는 공통 모델에 반영했습니다.

단위/요청 226개와 브라우저 주요 흐름 16개를 검증했습니다. 계층 순서 이동·저장·프로젝트 재선택 후 다시 읽기에서 업무 배열과 화면 순서, 선행 관계·완료 기록 보존을 확인했습니다. 기존 인증·동시 수정·Excel·초안 복구·저장 중 잠금·언어·모바일·500개 업무 흐름도 통과했습니다. 검증은 메모리 저장소와 로컬 테스트 계정·수신함을 사용했습니다.

## 0.21.2 추가 개선 · 2026-10-28

WBS 저장 중 버튼은 비활성화돼도 키보드 실행 취소와 셀·간트 입력 경로는 남아 있었습니다. 저장 응답을 기다리는 동안 초안이 바뀌면 응답 수신 후 초기화 과정에서 새 입력이 사라질 수 있어 저장 중 조작을 일관되게 잠갔습니다. 실행 취소·재저장·초안 취소·새 행 추가, 셀 입력·붙여넣기·간트 이동을 막고 저장 성공·실패 후에는 잠금을 해제합니다. 저장 대기 중 조작이 초안·이력을 바꾸지 않고, 실패 후 실행 취소를 다시 사용할 수 있는지 단위 검증을 추가했습니다.

단위/요청 테스트 224개와 Chromium 주요 흐름 15개를 통과했습니다. 브라우저에서 저장 응답을 보류한 채 실행 취소·재저장을 시도해 요청이 한 번만 발생하고 업무명이 보존되는지 확인했습니다. 저장 중 셀·후속 조정 입력은 비활성화되고 저장 완료 후 다시 활성화됩니다. 최종 입력·간트 잠금 보완 후 WBS·화면·편집 모듈 관련 32개도 재검증했습니다. 검증은 메모리 저장소와 로컬 테스트 계정·수신함 기준이며 운영 데이터는 사용하지 않았습니다.

## 0.21.1 추가 검토 · 2026-10-28

데스크톱 일정 기능을 추가하며 웹이 사용하는 공통 계산 코드와 주요 흐름을 다시 확인했습니다. 과부하 계산 자체는 근무일을 사용하지만 경고의 표시 기간 양끝에 주말·등록 휴무일이 남는 경우를 수정했습니다. 2026-10-24(토)~28(수)의 업무에서 26일·28일을 휴무로 지정하면 실제 과부하 근무일인 27일만 표시합니다. 원본 프로젝트를 바꾸지 않는지와 근무일 없는 구간을 표시하지 않는지도 회귀 테스트로 확인했습니다.

웹 단위/요청 221개, 실제 HTTP·로컬 TLS SMTP 15개, Chromium 브라우저 흐름 14개를 통과했습니다. 검토 범위에는 인증·CSRF·권한·동시 수정 충돌, Excel 양식/미리보기 경합·저장, JSON 초안 복구·재시도, 날짜 전환 중 입력 보존, 모바일 완료 체크, 500개 업무 화면과 과부하 경계 표시·원본 일정 보존이 포함됩니다. 테스트는 메모리 저장소·로컬 수신함을 사용했으며 이번 검토에서 실제 PostgreSQL·백업 복원·운영 배포는 실행하지 않았습니다.

## 0.19.1 재검토

복원 점검의 `migrations < 12` 지적은 맞다. 백업 이미지에 실제 마이그레이션 파일을 포함하고, 복원 DB의 버전 목록 전체가 이 파일 목록과 같은지 확인하도록 수정했다. 현재 013만 검사하는 상수로 바꾸지 않아 이후 파일 추가에도 동일한 검증을 적용한다. 복원 점검 중 스키마를 변경하지는 않는다.

`recovery-keys/`는 이전 버전의 사본을 안전하게 이동시키는 임시 위치다. 이동 직후 실제 경로와 함께 프로젝트 외부의 별도 보관 장소로 옮기라고 명시했다. 전체 호스트 백업의 수집 범위는 운영자가 관리해야 한다.

app.js의 WBS·대시보드 분리는 타당한 후속 개선이다. 줄 수 자체를 보안 결함으로 보지는 않으며, 현재 포맷·기능별 모듈과 테스트를 유지하면서 다음 유지보수에서 분리할 수 있다. 이번 검증에서는 실제 화면의 회원가입부터 완료 체크까지 다시 시연했다.

## 0.19.2 화면 분리

남은 WBS·대시보드 화면 분리를 수행했다. 대시보드는 명시적 프로젝트·요약·보고일을 받아 카드·차트·타임라인을 렌더링하며, WBS 화면은 기존 편집 클래스와 서버 연결을 묶는다. 공통 화면 요소도 독립시켜 다른 화면에서 재사용한다. app.js는 2,896줄에서 2,373줄로 줄었다. 새 기능이나 화면 변경 없이, 다섯 입력 조건에서 분리 전후 HTML의 SHA-256이 모두 같은지 확인했다. 저장 충돌·세션 만료·중복 요청·Excel 바이너리 전달 회귀 테스트와 실제 브라우저 동작을 추가로 확인했다.
