# 보안 운영 · 0.10.0

## 이번 보안 수정

- 근무일 계산을 전체 날짜 순회 대신 산술 계산으로 변경했습니다. 입력 날짜는 1900~2200년, 업무 기간 약 10년, 프로젝트 전체 일정·완료일·기준 계획 범위는 100년까지입니다.
- Excel 읽기·출력은 별도 Node 프로세스에서 실행합니다. 동시 작업 2개, 계정당 분당 20회, 실행 15초, 입력 8MB, 출력 32MB, 자식 JS 힙 192MB 제한이 있습니다. 압축 파일은 실제 해제 스트림 크기와 메타데이터 일치까지 검사합니다. 앱 컨테이너에는 메모리·CPU·프로세스 수 제한을 둡니다.
- 비밀번호 검증은 동시 2개·대기 24개로 제한합니다. scrypt-v2는 N=131072, r=8, p=1이며 기존 v1 비밀번호는 성공한 로그인에서 자동 업그레이드합니다. 평문 비밀번호를 보관하지 않습니다.
- 로그인 시도 횟수는 검증 전에 PostgreSQL에서 원자적으로 확보합니다. 계정당 15분 8회, 식별 가능한 클라이언트 IP당 15분 40회입니다. 로컬·사설 공유 진입점의 주소를 모든 사용자의 IP로 간주해 장시간 차단하지 않습니다.

## 신뢰할 프록시 설정

HTTPS로 공개하는 경우 TRUSTED_PROXIES에 **앱이 직접 연결받는 프록시의 정확한 IP**를 지정해야 기동합니다. 예: TRUSTED_PROXIES=127.0.0.1 또는 Docker 브리지의 프록시 주소. 여러 주소는 쉼표로 구분합니다. 프록시 외 직접 접근은 방화벽으로 차단하세요.

프록시는 X-Forwarded-For를 외부 입력에 추가하는 대신 **실제 클라이언트 IP 한 개로 덮어써야** 합니다. 기본 nginx 예제는 이 방식입니다. Apache 예제는 headers 모듈이 필요합니다. 신뢰하지 않는 송신자의 헤더는 사용하지 않으며, 신뢰한 프록시가 여러 IP 또는 잘못된 값을 보내면 요청을 거절합니다. Docker 내부 healthcheck에는 프록시 헤더를 요구하지 않습니다.

## 관리자 MFA

업데이트 시 기존 관리자 세션을 종료합니다. 다음 비밀번호 로그인에서 인증 앱에 설정 키를 수동으로 등록하고 6자리 코드를 입력해야 로그인됩니다. Google Authenticator, Microsoft Authenticator 등 표준 TOTP 앱을 사용할 수 있습니다. 설정은 SHA1 / 6자리 / 30초입니다. 서버 시각을 동기화하세요.

등록 후 복구 코드 10개를 **한 번만** 표시합니다. 인증 앱과 별도로 안전하게 보관하세요. 각각 한 번만 사용할 수 있습니다. MFA 챌린지는 5분·5회로 제한하고, 이미 사용한 인증 앱 코드도 다시 사용할 수 없습니다. 로그인 직후 다시 로그인해야 하면 다음 30초 코드를 기다리거나 복구 코드를 사용하세요.

MFA 키는 config/secrets/mfa.key에 생성되는 32바이트 난수입니다. npm run setup / npm run service:up가 없는 키를 생성합니다. Docker에는 설정 디렉터리가 읽기 전용으로 연결됩니다. 네이티브 실행도 먼저 setup을 사용하세요. MFA_KEY_FILE로 다른 위치를 지정할 수 있습니다. 키 파일은 Git에 포함하지 않으며 **DB 백업과 별도로 보호·백업**해야 합니다. DB에는 AES-256-GCM 암호문과 복구 코드 해시만 저장합니다.

기기와 복구 코드를 모두 잃었거나 MFA 암호화 키를 잃은 경우, 서버 운영자가 다음 명령으로 관리자 MFA와 세션을 초기화할 수 있습니다. 다음 로그인에서 다시 등록해야 합니다. 이 작업은 감사 로그에 남으며 서버·DB 운영 권한이 필요합니다.

    docker compose exec -T app node scripts/reset-mfa.mjs 관리자이메일 --confirm-reset

백업 복원 시 세션·인증 챌린지·제한 카운터를 제거하고, MFA 테이블이 있는 백업에서는 복구 코드도 무효화합니다. 기존 인증 앱은 보관한 같은 MFA 키로 복원할 때 사용할 수 있습니다. MFA 키가 없으면 키를 복구하거나 운영자 초기화가 필요합니다.

## 초안 보관

기본값은 sessionStorage로 현재 탭에서 보관합니다. 계정 관리에서 선택한 경우에만 localStorage에 보관합니다. 8시간 동안 입력이 없으면 만료되고, 앱을 다시 열 때 만료 사본을 삭제합니다. 로그아웃하면 해당 계정의 두 저장소 초안을 모두 삭제합니다. 이전 버전의 영구 저장 초안도 유효기간을 적용해 탭 저장소로 옮깁니다.

선택한 브라우저 보관은 암호화되지 않습니다. 만료는 앱의 복구를 제한하며, 닫힌 브라우저의 저장 파일을 정확히 만료 시각에 물리적으로 지우는 기능은 아닙니다. 기밀 업무에는 영구 보관을 선택하지 말고 공용 PC에서 로그아웃하세요. 인증 토큰·비밀번호·MFA 키는 초안 저장소에 저장하지 않습니다.

## 보안 감사 및 자동 검사

계정 → 관리자 설정 → 인증·보안의 **보안 감사 로그**에서 로그인·MFA·비밀번호/계정/외부 계정 연결 변경을 확인합니다. 최근 200건을 표시하고 90일 보관합니다. 실패 로그는 같은 진입점·오류 종류에 대해 분당 30건으로 제한해 로그 폭증을 방지합니다. 비밀번호·OTP·복구 코드·MFA 설정 키는 기록하지 않으며, IP와 로그인 계정은 해시로 기록합니다.

GitHub에는 테스트·실제 HTTP·PostgreSQL 통합 테스트·npm audit, CodeQL, 주간 Dependabot 검사를 설정합니다. Actions는 고정 커밋 SHA와 최소 권한을 사용합니다. 실제 인증 연결·키·DB 백업은 .gitignore에 의해 제외됩니다. 취약점 보고는 공개 이슈 대신 저장소의 비공개 보안 보고를 사용하세요.
