# 마일스톤 · 이슈 · 주간보고 · 투입 계획

웹·데스크톱의 **이슈 · 보고**에서 관리합니다. 웹 조회자는 내용을 조회하고 발행 보고서를 내려받을 수 있으며 저장·발행은 편집자·소유자만 가능합니다. 다른 관리 양식의 미저장 입력은 한 양식을 저장해도 유지합니다.

## 마일스톤

공수·기간이 0인 별도 유형입니다. 목표일·담당자·실제 완료일·복수 선행 업무를 지정합니다. 목표일에는 주말·휴무일도 사용할 수 있고 미래 실제 완료일은 허용하지 않습니다. 공수 기반 공정률이나 담당자 가용시간에는 가산하지 않으며, 완료 건수·지연 점검·임계 경로·프로젝트 예상 완료일에는 반영합니다. 하위 업무는 둘 수 없습니다.

마일스톤은 선행 업무가 끝나는 날짜의 완료 시점에 달성할 수 있습니다. 일반 후속 작업은 마일스톤 완료 다음 근무일부터 시작합니다. 미완료 마일스톤의 예상일은 보고 기준일 다음 날짜·목표일·선행 완료일 중 가장 늦은 날짜입니다. 일자 단위 계산이며 시각 단위 제약은 없습니다. 일반 업무의 시작일·종료일이 같은 경우는 기존처럼 1근무일 작업입니다.

WBS의 더 보기에서도 마일스톤을 추가할 수 있습니다. 완료 체크 화면에서 완료를 기록하거나 상세 편집에서 실제 완료일을 입력합니다. CSV·Excel·프로젝트 파일은 마일스톤 유형을 보존합니다. 단계별 산출물과 파일 첨부·검토 승인 기능은 이번 범위에 포함하지 않습니다.

## 이슈·리스크

제목·유형·영향도·담당자·기한·상태·조치 내용·관련 업무를 기록합니다. 리스크는 발생 가능성도 입력합니다. 상태는 미해결 / 조치 중 / 종료입니다. 리스크가 실제로 발생하면 유형을 이슈로 변경하고 조치 내용을 이어서 작성합니다. 업무나 인력 삭제 시 현재 연결만 해제하며 발행 보고서에 남긴 사본은 유지합니다.

## 주간보고

1. 오늘까지의 1~7일 기간을 선택하고 금주·차주 설명을 작성합니다.
2. **주간보고 미리보기**로 기간 내 완료 기록이 있는 업무, 미완료 업무, 차주 예정 업무, 현재 주요 이슈와 마일스톤을 확인합니다.
3. **이 내용으로 발행**으로 사본을 보관합니다. 미리보기 이후 데이터나 입력이 달라지면 다시 미리보기해야 합니다.
4. 발행 보고서는 HTML로 내려받아 브라우저에서 열거나 인쇄할 수 있습니다. 프로젝트 파일에도 함께 보관됩니다.

회색 계획선과 파란 실제선은 현재 업무 범위의 예상 공수를 같은 분모로 사용합니다. 보라색 기준 계획선은 기준 계획 저장 당시의 범위·공수를 분모로 사용하므로 범위가 바뀌면 직접 차감해 지연률로 해석하지 마세요. 실제선은 완료한 체크 항목의 예상 공수이고 실제 투입시간이 아닙니다. 부분 진행 상황·대외 협의·보고 설명은 사람이 작성합니다. 이슈 상태는 과거를 추정하지 않고 발행 시점의 목록을 담습니다.

발행 보고서의 수치·업무명·담당자명·이슈·설명은 이후 변경에 따라 다시 계산되지 않습니다. 수정·삭제는 허용하지 않으며 정정은 새 보고서를 발행합니다. 데스크톱 실행 취소·다시 실행도 발행 사본을 제거하지 않습니다. 프로젝트당 최대 100개입니다. 기존 프로젝트의 파일·요청 크기 제한도 적용됩니다. 발행은 암호학적 서명이나 외부 검수 승인 기능이 아닙니다.

## 월별 계획 M/M

인력별 투입 시작·종료일과 투입률을 등록합니다. 동일 인력의 겹치는 기간에 투입률 합계가 100%를 초과하면 거부합니다. 날짜별 가용시간을 예측·과부하 경고·계획 M/M에 공통으로 적용합니다.

- 해당 인력의 기간 계획이 없으면 기존 인력 정보의 기본 투입률을 사용합니다. 환산 기준만 저장하거나 빈 기간 목록을 가져와도 기본 투입률을 사용합니다.
- 기간 계획이 하나라도 있으면 날짜별 계획 투입률 합계가 기본 투입률을 대체합니다. 두 투입률을 곱하지 않으며, 기간 사이 공백과 전체 기간 밖은 0%입니다.
- 마지막 기간을 삭제하면 기본 투입률로 돌아갑니다. 등록된 계획에서 가용시간이 부족하면 예상 완료일은 계산 대기로 표시하므로, 필요한 후속 기간을 추가하세요.

월별 표의 **집계 기준**은 인력별로 **기간별 계획** 또는 **기본 투입률로 추정**을 표시합니다. 기간 계획이 없는 인력은 WBS 업무 기간 밖의 조회 월에도 기본 투입률로 계산되며, 등록한 투입 기간이나 실제 투입 실적을 뜻하지 않습니다. 합계에 추정값이 포함되면 **추정값 포함** 표시와 추정 시간·M/M을 함께 안내합니다. 기간별 계획으로 계산한 값이 0인 경우에도 집계 기준은 기간별 계획으로 유지합니다.

- 월 계획 시간 = 그 달의 근무일별 가용시간 합계 (일 근무시간 × 해당 날짜의 적용 투입률)
- 계획 M/M = 월 계획 시간 ÷ 설정한 1 M/M 시간
- 업무 계획 공수 = 기존 WBS 공수를 계획 근무일에 균등 배분해 그 달에 해당하는 양

주말·프로젝트 휴무일을 제외합니다. 160h는 편집 가능한 초기값으로 산업 표준을 뜻하지 않습니다. 계약·조직의 기준으로 변경하세요. 인력의 일 근무시간·휴무일·투입 계획을 바꾸면 가용시간과 예상일을 다시 계산합니다. M/M 환산 기준 변경은 보고 단위만 바꾸며 가용시간·예상일에는 영향을 주지 않습니다. WBS 계획 공수·계획 진척률은 기존 계획 일정을 유지하며, 투입 계획에 맞춰 날짜나 공수를 자동 변경하지 않습니다. 실제 투입시간·실적 M/M·급여·계약 금액은 수집하거나 산출하지 않습니다.

## 모바일과 파일

모바일 웹의 내 업무에서 **오늘 완료 기록**을 펼쳐 개별 체크 항목을 바로 완료할 수 있습니다. 현재 서버 데이터와 revision을 조회한 뒤 저장하며 다른 사람이 먼저 바꿨으면 덮어쓰지 않습니다. 담당 변경·조회 권한·중복 클릭도 검사합니다. 과거 완료일은 기존 매일 체크 화면에서 지정하세요.

네이티브 모바일은 계속 오프라인 앱입니다. 새 관리 정보와 보고서는 파일 가져오기·편집·내보내기에서 보존하고 마일스톤을 체크할 수 있지만, 이슈·주간보고·M/M 전용 편집 화면과 서버 연결은 이번에 추가하지 않습니다.

새 프로젝트 백업·`.pmcanvas` 파일은 **v3**으로 저장하며 v1·v2도 읽습니다. 새 관리 정보를 누락하지 않도록 v3을 지원하는 웹·데스크톱·모바일 버전을 함께 사용하세요. 서버는 기존 planning JSON 열에 관리 정보와 마일스톤 완료일을 보관하므로 추가 SQL 마이그레이션은 없습니다. 서버 업데이트 전에는 기존 절차대로 DB 백업을 보관하세요.
